<Note>
**Starting with v5.1.0, {method} accepts a `listener:` parameter** that takes a `MessageSentListener`. The `listener:` parameter requires `cometchat_sdk` 5.1.0 or later. With offline support off, the listener behaves exactly like the old callback: the sent message arrives in `onMessageSent` (the drop-in for `onSuccess`) and `onError` is unchanged. With offline support on, `onMessagePending` fires first — the message is persisted locally. A message sent without a connection stays `pending` and is sent when the connection returns: `onError` fires once with code `ERR_CONNECTION` (details `ERROR_INTERNET_UNAVAILABLE`) as a not-connected notice, and `onMessageSent` follows once the message is sent. In `onError`, code `ERR_CONNECTION` means the message is queued; a real failure also reaches `OfflineMessageListener.onOutboxMessageFailed`, with the message's `status` set to `failed`. A send without a `listener:` is never queued. See [Send While Offline](/sdk/flutter/offline-send).
</Note>
