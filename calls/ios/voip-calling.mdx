The **Push Notifications SDK** rings incoming calls on iOS. It receives the VoIP push, rings
CallKit, and handles Answer and Decline, whether your app is in the foreground, in the
background, or terminated. Your app writes one method: present the call screen and join the
session when the user answers.

You do not write a `PKPushRegistryDelegate` or a `CXProviderDelegate`.

<Note>
  This page is the receiving side of [Ringing](/calls/ios/ringing). For chat message
  notifications, see the [iOS Push Notifications SDK](/notifications/ios-push-notifications-sdk);
  the same SDK handles both.
</Note>

## Requirements

| | |
|---|---|
| Minimum iOS | **15.1** |
| Xcode | **16.4+**. The Calls SDK binary is built with Swift 6.1.2 |
| Calls SDK | `CometChatCallsSDK` **5.1.3+** |
| Chat SDK | Not needed |
| Device | **A physical device.** PushKit and CallKit don't work on the Simulator |

## Install

Add two products of the `CometChatPushNotifications` package to your app target:

| Product | Contains |
|---|---|
| `CometChatPushNotificationsSwift` (Core) | Configuration, token registration, diagnostics |
| `CometChatPushNotificationsCalls` (Calls) | PushKit, CallKit, answer and decline |

If the app also shows chat notifications, add `CometChatPushNotificationsChat` too. See the
[iOS Push Notifications SDK](/notifications/ios-push-notifications-sdk).

<Tabs>
<Tab title="Swift Package Manager">
In Xcode, **File → Add Package Dependencies** and add:

```
https://github.com/cometchat/push-notifications-sdk-ios
```

Pick version **2.0.0** or later, and add **`CometChatPushNotificationsSwift`** and
**`CometChatPushNotificationsCalls`** to your app target.
</Tab>
<Tab title="CocoaPods">
```ruby
platform :ios, '15.1'

target 'YourApp' do
  use_frameworks!
  pod 'CometChatPushNotificationsSwift', '2.0.0'
  pod 'CometChatPushNotificationsCalls', '2.0.0'
end
```

Then `pod install`. The Calls pod pulls `CometChatCallsSDK` automatically.

## Before you start

Each item below silences calls **without an error** if it is missing. `ensureRingReady` (see
[Troubleshooting](#troubleshooting)) reports most of them.

1. **CometChat dashboard:** go to **Notifications → Settings**, enable Push Notifications, and add
   an **APNs** provider with a **token-based `.p8` key**. One `.p8` key serves both the VoIP token
   and the APNs device token. Copy the **Provider ID**.

   {/* TODO(RC): the integration guide shared with the 2.0.0-alpha.5 release says to add TWO providers (APNs Device and APNs VoIP) and pass the VoIP one's ID; the push README and capabilities.md still say one .p8 provider serves both. The SDK sends the single `providerId` with both the apns_ios_device and apns_ios_voip tokens, so the answer is on the backend. Confirm with the Push team before publishing. */}
2. **Push Notifications** capability, under *Signing & Capabilities*. It is needed for the VoIP
   token.
3. **Background Modes → Voice over IP.** Without it, PushKit can't wake a terminated app.
4. **Background Modes → Remote notifications**, if the app also receives chat notifications.
5. **`NSMicrophoneUsageDescription`** and **`NSCameraUsageDescription`** in `Info.plist`. iOS
   terminates the app when the call accesses the microphone or camera without them. Add both,
   even for audio-only apps.

The SDK links `PushKit`, `CallKit` and `AVFAudio` for you.

## 1. Initialize

Call `initialize` from `application(_:didFinishLaunchingWithOptions:)`, and nowhere later:

```swift
import CometChatPushNotificationsSwift
import CometChatPushNotificationsCalls

@main
final class AppDelegate: UIResponder, UIApplicationDelegate {

    let pushDelegate = CallPushDelegate()   // see step 3 — the SDK holds it weakly

    func application(_ application: UIApplication,
                     didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
        CometChatPushNotifications.shared.delegate = pushDelegate
        CometChatPushNotifications.shared.initialize(
            config: PNConfiguration.builder(appId: "YOUR_APP_ID", region: "YOUR_REGION")
                .providerId("YOUR_PROVIDER_ID")
                .callKit(name: "Your App", iconTemplateImageName: "CallKitIcon",
                         ringtone: nil, includeInRecents: true, supportsVideo: true)
                .build()
        )
        return true
    }
}
```

<Warning>
  **`initialize` must run in `didFinishLaunching`.** The SDK creates the PushKit registry inside
  it, and iOS delivers the VoIP push that launched the app only if the registry exists when
  `didFinishLaunching` returns. If you initialize later, the first call after a cold start is
  lost.
</Warning>

`initialize` also asks for notification permission and registers for remote notifications.
A calls-only app doesn't need either, because CallKit rings without notification permission. Add
`.requestNotificationPermission(false)` to skip the prompt.

<Tip>
  If you already have the Calls SDK's `CallAppSettings`,
  `PNConfigurationBuilder.from(callAppSettings)` reuses its app ID and region. It returns `nil`
  on Calls SDK versions without ringing support.
</Tip>

## 2. Log in — tokens register automatically

The SDK captures the VoIP token itself and registers it each time a user logs in to the Calls
SDK (or the Chat SDK). You don't call `registerPushToken`.

On **logout**, unregister first and wait for it to finish. Unregistering needs the user's auth
token, which logout clears:

```swift
CometChatPushNotifications.shared.unregisterTokens(completion: { _ in
    CometChatCalls.logout(onSuccess: { _ in /* ... */ }, onError: { _ in /* ... */ })
})
```

If you log out first, the device keeps ringing for the user who just logged out.

## 3. Present the call

Adopt `CometChatPushNotificationsCallsDelegate`. The SDK calls `presentCall(_:)` the moment the
user taps **Answer**, in every app state, including on the lock screen:

```swift
import CometChatCallsSDK
import CometChatPushNotificationsSwift
import CometChatPushNotificationsCalls

final class CallPushDelegate: NSObject, CometChatPushNotificationsCallsDelegate {

    // The user answered. Present your call screen and join the session.
    func presentCall(_ call: IncomingCall) -> Bool {
        CallScreenPresenter.shared.present(call)   // your code
        return true
    }

    // The call is over (or never connected). Dismiss your call screen.
    func callDidEnd(_ call: IncomingCall, reason: CallEndReason) {
        CallScreenPresenter.shared.dismiss(sessionId: call.sessionId)
    }

    // Optional — the fastest way to catch a wrong Provider ID or a missing entitlement.
    func onPushTokenRegistrationFailed(platform: CometChatPushTokenPlatform, error: PNError) {
        print("\(platform.rawName) token registration failed: \(error)")
    }
}
```

In your call screen, join by session ID as soon as it appears:

```swift
CometChatCalls.joinSession(
    sessionID: call.sessionId,
    callSetting: SessionSettingsBuilder().build(),   // ignored — see below
    container: callViewContainer,
    onSuccess: { _ in },
    onError: { error in
        print("Join failed: \(error?.errorDescription ?? "")")
    }
)
```

Rules for `presentCall`:

- **Join within 20 seconds.** If you return `false`, have no delegate, or don't join in time, the
  SDK ends the call as `failed`. It doesn't leave a silent call on screen.
- **Join right away, even if the phone is locked.** The audio connects before the user sees your
  screen.
- **Present from anywhere.** The answer can arrive in a process the push launched moments ago,
  before your UI is ready. Present on the key window's top view controller, or publish the call
  and let your root view present it when it is ready.
- `presentCall` fires at most once per call.

<Note>
  **The SDK prepares the session while the phone rings**, using the call type: video or audio,
  with the camera off for audio calls and audio on the speaker. Joining by session ID takes that
  session over, so the call connects almost instantly, but the settings you pass to `joinSession`
  are ignored.
</Note>

`IncomingCall` carries:

| Property | Description |
|---|---|
| `sessionId` | The session to join |
| `callerUid` / `callerName` / `callerAvatarUrl` | Who is calling |
| `callType` / `isVideo` | Audio or video |
| `receiverType` / `isPeerCall` | 1:1 or group |
| `initiatedAtMs` / `ringTimeoutMs` / `expiresAtMs` | The ring window. It runs from the server's `initiatedAt`, so it closes at the same moment on every device |

`callDidEnd` reasons are listed under [Ringing → Status values](/calls/ios/ringing#status-values).

### Declining

The user declines from the CallKit screen. For a 1:1 call, the SDK ends the call for the caller
as `rejected`, or `busy` when the user is already on another call. For a group call, the SDK only
stops the ring on this device and sends nothing, so the call goes on for the other members. You
write no code for either.

When a 1:1 call rings out on this device, the SDK ends it as `unanswered`. A group call that rings
out is left running for the others.

The incoming call always rings through CallKit, even when your app is in the foreground. To answer
or decline from your own UI, call `CometChatPushNotificationsCalls.answer(sessionId:)` or
`decline(sessionId:)`.

## Audio session

CallKit owns the audio session. The SDK configures it when the user answers and hands it to the
Calls SDK.

<Warning>
  Never call `AVAudioSession.setActive` yourself during a call. On a lock-screen answer it causes
  one-way audio.
</Warning>

## Own the PushKit registry yourself (advanced)

If your app already has a `PKPushRegistry` (for example, for another VoIP provider), set
`.pushKitOwnership(.app)` and forward to the SDK from your own `PKPushRegistryDelegate`:

```swift
func pushRegistry(_ registry: PKPushRegistry, didUpdate credentials: PKPushCredentials, for type: PKPushType) {
    CometChatPushNotifications.shared.handleVoIPToken(credentials.token)
}

func pushRegistry(_ registry: PKPushRegistry, didReceiveIncomingPushWith payload: PKPushPayload,
                  for type: PKPushType, completion: @escaping () -> Void) {
    let handled = CometChatPushNotifications.shared.handleIncomingVoIPPush(payload.dictionaryPayload,
                                                                            completion: completion)
    if !handled {
        // Not a CometChat call. Report your own call to CallKit, then call completion().
    }
}
```

<Warning>
  When `handleIncomingVoIPPush` returns `false`, you **must** report a call to CallKit before you
  call `completion`. iOS terminates an app that receives a VoIP push without reporting a call.
</Warning>

## Configuration reference

The call options on `PNConfiguration` / `PNConfigurationBuilder`:

| Option | Default | Description |
|---|---|---|
| `appId`, `region` | — | Required |
| `providerId` | `nil` | Required to register tokens |
| `callKit` | System defaults | `CallKitBranding`: `localizedName`, `iconTemplateImageName` (a 40×40 pt template image in your asset catalog), `ringtoneSound` (a sound file in your bundle; `nil` uses the user's ringtone), `includesCallsInRecents`, `supportsVideo` |
| `pushKitOwnership` | `.sdk` | `.app` to keep your own `PKPushRegistry` |
| `defaultRingTimeoutMs` | `45000` | How long to ring when the push doesn't carry a ring timeout |
| `requestCallPermissions` | `true` | Ask for the microphone (and the camera for video calls) when the user answers. Set `false` if your app asks itself |
| `requestNotificationPermission` | `true` | Set `false` in a calls-only app to skip the notification prompt |
| `autoRegisterTokens` | `true` | Register on login, unregister on logout |
| `authToken` | `nil` | Register under an auth token you mint yourself |
| `overrideClientHost` | `nil` | Register tokens on a dedicated or staging host. Pass the same host you give the Calls SDK. The `PNConfiguration` initializer calls it `clientHost:` |

## Troubleshooting

`ensureRingReady` names the first thing that would stop a call ringing on this device:

```swift
CometChatPushNotifications.shared.ensureRingReady(completion: { result in
    if case .success(let readiness) = result, readiness != .ready {
        print("Calls won't ring: \(readiness.name)")
    }
})
```

| Value | Meaning | Fix |
|---|---|---|
| `ready` | No problem found | — |
| `backgroundModeMissing` | `UIBackgroundModes` has no `voip` | Enable **Background Modes → Voice over IP** |
| `voipEntitlementMissing` | The build has no `aps-environment` entitlement | Add the **Push Notifications** capability and re-sign |
| `microphoneDenied` | The microphone is denied | The callee joins muted. Ask the user to allow it in Settings |
| `providerMissing` | No `providerId` in the configuration | Pass the Provider ID from the dashboard |
| `notificationsOff` | Notifications are denied | Calls still ring. Chat notifications don't appear |

<Note>
  `ensureRingReady` checks this device's setup. It doesn't check that a user is logged in or that
  the token is registered. Watch `onPushTokenRegistrationFailed` for that.
</Note>

For a support ticket, attach `CometChatPushNotifications.shared.getDiagnostics()`. It holds no
tokens, auth values or payloads.

| Symptom | Check |
|---|---|
| Never rings | Physical device; `ensureRingReady`; the Provider ID matches a `.p8` provider; the user is logged in |
| Rings only while the app is open | **Background Modes → Voice over IP**; `initialize` runs in `didFinishLaunching` |
| Answer shows nothing, then the call ends | `presentCall` is implemented, returns `true`, and the join starts within 20 seconds |
| One-way audio after a lock-screen answer | Your app calls `AVAudioSession.setActive`. Remove it |
| Still rings after logout | Call `unregisterTokens` and wait for it **before** logging out |
