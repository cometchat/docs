With offline support turned on, the UI Kit keeps showing the user's chats when the network drops. Conversations and messages load from a cache on the device first and are refreshed from the server when it is reachable, and messages sent while offline are delivered automatically once the connection returns.

The UI Kit builds on the [offline support in the JavaScript SDK](/sdk/javascript/offline-support). You configure it in UI Kit settings; the components handle the rest.

## Configure Offline Support

Call `setOfflineConfig()` on the `UIKitSettingsBuilder` before `CometChatUIKit.init()`. Set `enabled` explicitly.

```typescript
import { CometChat } from "@cometchat/chat-sdk-javascript";
import { CometChatUIKit, UIKitSettingsBuilder } from "@cometchat/chat-uikit-angular";

const UIKitSettings = new UIKitSettingsBuilder()
  .setAppId("APP_ID")
  .setRegion("REGION")
  .setAuthKey("AUTH_KEY")
  .subscribePresenceForAllUsers()
  .setOfflineConfig({
    enabled: true,
    mediaCaching: CometChat.MediaCachingMode.AUTO,
  })
  .build();

CometChatUIKit.init(UIKitSettings)?.then(() => {
  // login your user
});
```

The UI Kit passes this object to the SDK, so it accepts every option in the [SDK configuration table](/sdk/javascript/offline-support#configuration-options) — the outbox size, media caching, encryption and so on. Any object you pass turns offline support on unless it sets `enabled: false`.

<Note>
  The UI Kit applies the offline configuration only when the installed
  `@cometchat/chat-sdk-javascript` exposes `AppSettingsBuilder.setOfflineConfig()`.
  With an older SDK the setting — including the default — is silently ignored
  and the UI Kit works online only.
</Note>

<Warning>
  If you don't call `setOfflineConfig()`, the Angular UI Kit enables offline
  support with `mediaCaching` set to `AUTO`, which stores the user's
  conversations, messages and media in the browser. To keep everything
  online-only, turn it off explicitly:

  ```typescript
  new UIKitSettingsBuilder()
    // ...
    .setOfflineConfig({ enabled: false })
    .build();
  ```
</Warning>

<Note>
  Whether offline support is actually running can change after init — for
  example, CometChat can switch it off for your app from the server. The UI
  Kit checks `CometChat.isOfflineEnabled()` each time it needs to; do the same
  in your own code instead of reading back the value you configured.
</Note>

## What Changes in the Components

| Feature | Components | Behaviour |
| --- | --- | --- |
| Cached conversations | [Conversations](/ui-kit/angular/components/cometchat-conversations) | The list renders from the cache immediately, then updates with the server's list. Offline, the cached list stays on screen. |
| Cached messages | [Message List](/ui-kit/angular/components/cometchat-message-list) | A conversation opens with its cached messages, then updates with the server's page. |
| Sending while offline | [Message Composer](/ui-kit/angular/components/cometchat-message-composer), [Message List](/ui-kit/angular/components/cometchat-message-list) | A message sent offline appears in the list straight away and is queued. It is sent automatically when the connection returns, and its receipt updates as usual. |
| Cached media | [Message List](/ui-kit/angular/components/cometchat-message-list) | Images, videos, audio and files that were downloaded while online are shown from the device when offline (with `mediaCaching` set to `AUTO`). |
| Attachment uploads | [Message Composer](/ui-kit/angular/components/cometchat-message-composer) | A file that failed to upload can be retried, and staged attachments are restored when the user reopens the conversation. |

## Logging Out

The SDK deletes the cached data, cached media and any queued messages when the user logs out, and when a different user logs in. You don't need to clear anything yourself.

## Limitations

- The cache only holds what the user has loaded while online, plus the changes picked up when the device reconnects. A user who has never logged in online has nothing to show offline.
- Only sending messages works offline. Actions such as editing, deleting, reacting and pinning need a connection.
- Search reads from the server only, so it doesn't work while offline.
- There is no built-in offline banner and no "retry" action for a failed message. Use `CometChat.isOfflineEnabled()` and the SDK's [connection status](/sdk/javascript/connection-status) if you want to build your own.
