## Overview

The CometChatIncomingCall component renders an incoming call notification card when a user receives a voice or video call. It displays the caller's name, avatar, and call type icon using a `CometChatListItem`, along with Accept and Decline buttons. After accepting, the ongoing call screen opens: the [call host](/ui-kit/angular/components/cometchat-call-host) draws it, or the card itself when no call host is mounted.

A 1:1 call rings through the Calls SDK. While the card rings, the kit prepares the call's session, so Accept joins at once. A tab that is already in a call, placing one or showing an incoming call answers a new 1:1 call busy, and the card never shows it. See [How calls ring](/ui-kit/angular/call-features#how-calls-ring).

### Key Features

- **Caller Information**: Displays caller name, avatar, and call type (audio/video) icon
- **Accept & Decline**: Built-in buttons for accepting or declining the call
- **Ringtone Support**: Plays an incoming call ringtone with custom sound support
- **Ongoing Call Transition**: Automatically shows the ongoing call screen after accepting
- **Custom Handlers**: Override default accept/decline behavior with custom callbacks
- **Template Overrides**: Replace any visual section with custom templates
- **Focus Management**: Dialog focus trap with Escape key to decline
- **Global Config Priority**: Supports a three-tier priority system (Input > GlobalConfig > Default)

## Basic Usage

```typescript expandable
import { Component } from '@angular/core';
import { CometChat } from '@cometchat/chat-sdk-javascript';
import { CometChatIncomingCallComponent } from '@cometchat/chat-uikit-angular';

@Component({
  selector: 'app-incoming-call-demo',
  standalone: true,
  imports: [CometChatIncomingCallComponent],
  template: `
    <cometchat-incoming-call
      [call]="incomingCall"
      (callAccepted)="onCallAccepted($event)"
      (callDeclined)="onCallDeclined($event)"
    ></cometchat-incoming-call>
  `
})
export class IncomingCallDemoComponent {
  incomingCall!: CometChat.Call;

  onCallAccepted(call: CometChat.Call): void {
    console.log('Call accepted:', call.getSessionId());
  }

  onCallDeclined(call: CometChat.Call): void {
    console.log('Call declined:', call.getSessionId());
  }
}
```

## Events

| Event | Payload Type | Description |
|-------|-------------|-------------|
| `callAccepted` | `CometChat.Call` | Emitted when the user accepts the incoming call. |
| `callDeclined` | `CometChat.Call` | Emitted when the user declines the incoming call. |
| `error` | `CometChat.CometChatException` | Emitted on any error during sound playback, accept, or decline, including `CALL_NOT_RINGING` when the call stopped ringing before Accept. |

### Custom Accept and Decline

`onAccept` and `onDecline` run instead of the kit's own answer and decline:

- **`onAccept`, for a 1:1 call:** the kit stops ringing and keeps the session it prepared while the call rang. Your handler joins it with `CometChatCalls.getActiveSession()?.join(container)`; see [Join the session](/calls/javascript/ringing#join-the-session). The kit doesn't read the call's status before you join, so a call the caller has just cancelled can still be joined.
- **`onDecline`, for a 1:1 call:** the kit still leaves the session it prepared. Nothing declines the call, but leaving the prepared session closes a 1:1 call's room, so the call ends for the caller and the user's other devices too, recorded as unanswered.
- **For a call from an app on legacy ringing**, they replace `CometChat.acceptCall()` and `CometChat.rejectCall()`, as before.

Either way, the card stays up until your app closes it with `IncomingCallService.setIncomingCall(null)`. Until then, later 1:1 calls are answered busy.

```typescript expandable
import { Component, ElementRef, ViewChild, inject } from '@angular/core';
import { CometChat } from '@cometchat/chat-sdk-javascript';
import { CometChatCalls } from '@cometchat/calls-sdk-javascript';
import { CometChatIncomingCallComponent, IncomingCallService } from '@cometchat/chat-uikit-angular';

@Component({
  selector: 'app-custom-incoming-call',
  standalone: true,
  imports: [CometChatIncomingCallComponent],
  template: `
    <cometchat-incoming-call [onAccept]="accept"></cometchat-incoming-call>
    <div #callContainer class="my-call-container"></div>
  `
})
export class CustomIncomingCallComponent {
  @ViewChild('callContainer') callContainer!: ElementRef<HTMLElement>;
  private incomingCallService = inject(IncomingCallService);

  accept = (call: CometChat.Call): void => {
    // Close the card, or later calls are answered busy.
    this.incomingCallService.setIncomingCall(null);
    // Join the session the kit prepared while the call rang.
    void CometChatCalls.getActiveSession()?.join(this.callContainer.nativeElement);
  };
}
```

### Custom Templates

```html expandable
<cometchat-incoming-call
  [call]="incomingCall"
  [subtitleView]="customSubtitle"
  [acceptButtonView]="customAccept"
>
  <ng-template #customSubtitle let-ctx>
    <span>{{ ctx.callType === 'video' ? '📹 Video Call' : '📞 Audio Call' }}</span>
  </ng-template>

  <ng-template #customAccept let-ctx>
    <button class="my-accept-btn" (click)="acceptCall(ctx.call)">
      Accept {{ ctx.callerName }}'s call
    </button>
  </ng-template>
</cometchat-incoming-call>
```

A custom Accept or Decline button replaces the card's own, so its handler answers the call itself. Answer through `IncomingCallService`, which answers a 1:1 call on the Calls SDK as the card's own button does:

```typescript
private incomingCallService = inject(IncomingCallService);

acceptCall(call: CometChat.Call): void {
  this.incomingCallService.acceptCall(call.getSessionId()).catch(error => console.error(error));
}
```

`IncomingCallService.declineCall(sessionId)` declines the same way.

## Accessibility

### Keyboard Navigation

| Key | Action |
|-----|--------|
| `Enter` | Activate the focused button (Accept or Decline) |
| `Space` | Activate the focused button (Accept or Decline) |
| `Tab` | Move focus between Accept and Decline buttons |
| `Escape` | Decline the incoming call |

### ARIA Attributes

- `role="alertdialog"` on the notification container
- `aria-labelledby` references the caller name heading
- Focus is trapped within the dialog while visible
- Initial focus is set to the Accept button

### Screen Reader Support

- Incoming call is announced via a live region with caller name and call type
- Call ended is announced when the call terminates
