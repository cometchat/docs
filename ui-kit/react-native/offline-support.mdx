With offline support turned on, the UI Kit keeps showing the user's chats when the network drops. Conversations and messages load from a cache on the device first and are refreshed from the server when it is reachable, and messages sent while offline are delivered automatically once the connection returns.

The UI Kit builds on the [offline support in the React Native SDK](/sdk/react-native/offline-support). You turn it on in UI Kit settings; the components handle the rest.

## Install the Dependencies

| Package | Version | Needed for |
| --- | --- | --- |
| `@react-native-community/netinfo` | Any | **Required by the UI Kit**, even with offline support off — the Message List uses it to detect when the network returns, and the app bundle fails to build without it. |
| `@op-engineering/op-sqlite` | 9.0.0 or later | **Required for offline support.** The SDK's local database. |
| `react-native-fs` | Any | Caching media files on the device. |
| `react-native-keychain` | Any | [Encrypting the cache](/sdk/react-native/offline-support#encrypt-the-cache) only. |

Offline support needs **React Native 0.74 or later**, because current versions of `@op-engineering/op-sqlite` require it.

```bash
npm install @react-native-community/netinfo @op-engineering/op-sqlite react-native-fs
cd ios && pod install
```

These are native modules, so rebuild the app after installing them. In an Expo app, install them with `npx expo install` and rebuild your [development build](https://docs.expo.dev/develop/development-builds/introduction/) or EAS build — they don't run in Expo Go, where offline support stays off.

<Warning>
  Without `@op-engineering/op-sqlite`, offline support stays off and the UI Kit
  works online only. Nothing is logged, so check `CometChat.isOfflineEnabled()`
  after login to confirm offline support is running.
</Warning>

## Enable Offline Support

Add the `offline` field to your `UIKitSettings`:

<Tabs>
<Tab title="TypeScript">
```tsx
import { CometChatUIKit, UIKitSettings } from "@cometchat/chat-uikit-react-native";
import { CometChat } from "@cometchat/chat-sdk-react-native";

const uiKitSettings: UIKitSettings = {
  appId: "APP_ID",
  authKey: "AUTH_KEY",
  region: "REGION",
  subscriptionType: CometChat.AppSettings.SUBSCRIPTION_TYPE_ALL_USERS as UIKitSettings["subscriptionType"],
  offline: {
    enabled: true,
    mediaCaching: CometChat.MediaCachingMode.AUTO,
  },
};

CometChatUIKit.init(uiKitSettings)
  .then(() => {
    console.log("CometChat UI Kit initialized with offline support.");
  })
  .catch((error) => {
    console.error("CometChat UI Kit initialization failed:", error);
  });
```
</Tab>
<Tab title="JavaScript">
```jsx
import { CometChatUIKit } from "@cometchat/chat-uikit-react-native";
import { CometChat } from "@cometchat/chat-sdk-react-native";

const uiKitSettings = {
  appId: "APP_ID",
  authKey: "AUTH_KEY",
  region: "REGION",
  subscriptionType: CometChat.AppSettings.SUBSCRIPTION_TYPE_ALL_USERS,
  offline: {
    enabled: true,
    mediaCaching: CometChat.MediaCachingMode.AUTO,
  },
};

CometChatUIKit.init(uiKitSettings)
  .then(() => {
    console.log("CometChat UI Kit initialized with offline support.");
  })
  .catch((error) => {
    console.error("CometChat UI Kit initialization failed:", error);
  });
```
</Tab>
</Tabs>

`offline` accepts three forms:

| Value | Result |
| --- | --- |
| `true` | Offline support with the SDK's default options. |
| An options object | The options you set, with defaults for the rest. Include `enabled: true` — don't rely on the default value of `enabled`. Every option in the [SDK configuration table](/sdk/react-native/offline-support#configuration-options) is supported. |
| A `CometChat.OfflineConfig` | Passed to the SDK as is. Create it with `enabled: true`. |

If you leave `offline` out, or set it to `false`, offline support stays off and the UI Kit works exactly as before.

If you initialize with `CometChatUIKit.initFromSettings()`, put the same value under `chatSDK.offline` in the settings object instead:

```json
{
  "chatSDK": {
    "offline": { "enabled": true }
  }
}
```

<Warning>
  The UI Kit applies the `offline` setting only when the installed
  `@cometchat/chat-sdk-react-native` exposes `CometChat.OfflineConfig`. With
  an older SDK the setting is silently ignored and the UI Kit works online
  only — check `CometChat.isOfflineEnabled()` after login if you need to be
  sure.
</Warning>

<Note>
  Whether offline support is actually running can change after init — for
  example, CometChat can switch it off for your app from the server. The UI
  Kit checks `CometChat.isOfflineEnabled()` each time it needs to; do the same
  in your own code instead of reading back the value you configured.
</Note>

## What Changes in the Components

| Feature | Components | Behaviour |
| --- | --- | --- |
| Cached conversations | [Conversations](/ui-kit/react-native/conversations) | The list renders from the cache immediately, then updates with the server's list. Offline, the cached list stays on screen. |
| Cached messages | [Message List](/ui-kit/react-native/message-list) | A conversation opens with its cached messages, then updates with the server's page. |
| Sending while offline | [Message Composer](/ui-kit/react-native/message-composer), [Message List](/ui-kit/react-native/message-list) | A message sent offline appears in the list straight away with a clock icon and is queued — even if the app is closed. It is sent automatically when the connection returns, and its receipt updates as usual. |
| Pending and failed messages | [Message List](/ui-kit/react-native/message-list), [Conversations](/ui-kit/react-native/conversations) | A queued message shows a clock icon in its bubble, and a message that failed to send shows an error icon. The conversation's row shows the same icon in place of the last message's receipt while it has a queued or failed message. The icons follow your receipt styles (`waitIcon`, `errorIcon`). |
| Cached media | [Message List](/ui-kit/react-native/message-list) | Images, videos, audio and files that were downloaded while online are shown from the device when offline (with `mediaCaching` set to `AUTO`, the default). |
| Attachment uploads | [Message Composer](/ui-kit/react-native/message-composer) | A file that failed to upload can be retried, and staged attachments are restored when the user reopens the conversation. |

## Logging Out

The SDK deletes the cached data, cached media and any queued messages when the user logs out, and when a different user logs in. You don't need to clear anything yourself.

## Limitations

- The cache only holds what the user has loaded while online, plus the changes picked up when the device reconnects. A user who has never logged in online has nothing to show offline.
- Only sending messages works offline. Actions such as editing, deleting, reacting and pinning need a connection.
- Search reads from the server only, so it doesn't work while offline.
- There is no built-in offline banner and no "retry" action for a failed message. Use `CometChat.isOfflineEnabled()`, the SDK's [connection status](/sdk/react-native/connection-status) and its [retry methods](/sdk/react-native/offline-support#failed-messages-and-retry) if you want to build your own.
