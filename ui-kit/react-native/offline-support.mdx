| Field | Value |
| --- | --- |

| Component props | None — offline support is turned on in UI Kit settings only |
| Not included | No offline banner and no "retry" action for a failed message |

</Accordion>

With offline support turned on, the UI Kit keeps showing the user's chats when the network drops. Conversations and messages load from a cache on the device first and are refreshed from the server when it is reachable, and messages sent while offline are delivered automatically once the connection returns.

The UI Kit builds on the [offline support in the React Native SDK](/sdk/react-native/offline-support). You turn it on in UI Kit settings; the components handle the rest.

## Install the Dependencies

The SDK stores the cache with `@op-engineering/op-sqlite` and caches media files with `react-native-fs`. Install both in your app:

```bash
npm install @op-engineering/op-sqlite react-native-fs
cd ios && pod install
```

Both are native modules. In an Expo app, rebuild your [development build](https://docs.expo.dev/develop/development-builds/introduction/) after installing them — they don't run in Expo Go. Without `@op-engineering/op-sqlite`, offline support stays off and the UI Kit works online only.

## Enable Offline Support

Add the `offline` field to your `UIKitSettings`:

<Tabs>
<Tab title="TypeScript">
```tsx
import { CometChatUIKit, UIKitSettings } from "@cometchat/chat-uikit-react-native";
import { CometChat } from "@cometchat/chat-sdk-react-native";

const uiKitSettings: UIKitSettings = {
  appId: "APP_ID",
  authKey: "AUTH_KEY",
  region: "REGION",
  subscriptionType: CometChat.AppSettings.SUBSCRIPTION_TYPE_ALL_USERS as UIKitSettings["subscriptionType"],
  offline: {
    enabled: true,
    mediaCaching: CometChat.MediaCachingMode.AUTO,
  },
};

CometChatUIKit.init(uiKitSettings)
  .then(() => {
    console.log("CometChat UI Kit initialized with offline support.");
  })
  .catch((error) => {
    console.error("CometChat UI Kit initialization failed:", error);
  });
```
</Tab>
<Tab title="JavaScript">
```jsx

  });
```
</Tab>
</Tabs>

`offline` accepts three forms:

| Value | Result |
| --- | --- |
| `true` | Offline support with the SDK's default options. |
| An options object | Offline support **on**, unless the object sets `enabled: false`, with the options you set and defaults for the rest. Every option in the [SDK configuration table](/sdk/react-native/offline-support#configuration-options) is supported. |
| A `CometChat.OfflineConfig` | Passed to the SDK as is. |

If you leave `offline` out, offline support stays off and the UI Kit works exactly as before. A plain object turns offline support on unless it sets `enabled: false` — unlike `new CometChat.OfflineConfig({...})`, which stays off unless you set `enabled: true`.

<Warning>
  The UI Kit applies the `offline` setting only when the installed
  `@cometchat/chat-sdk-react-native` exposes `CometChat.OfflineConfig`. With
  an older SDK the setting is silently ignored and the UI Kit works online
  only — check `CometChat.isOfflineEnabled()` after login if you need to be
  sure.
</Warning>

<Note>
  Whether offline support is actually running can change after init — for
  example, CometChat can switch it off for your app from the server. The UI
  Kit checks `CometChat.isOfflineEnabled()` each time it needs to; do the same
  in your own code instead of reading back the value you configured.
</Note>

## What Changes in the Components

| Feature | Components | Behaviour |
| --- | --- | --- |
| Cached conversations | [Conversations](/ui-kit/react-native/conversations) | The list renders from the cache immediately, then updates with the server's list. Offline, the cached list stays on screen. |
| Cached messages | [Message List](/ui-kit/react-native/message-list) | A conversation opens with its cached messages, then updates with the server's page. |
| Sending while offline | [Message Composer](/ui-kit/react-native/message-composer), [Message List](/ui-kit/react-native/message-list) | A message sent offline appears in the list straight away and is queued — even if the app is closed. It is sent automatically when the connection returns, and its receipt updates as usual. |
| Cached media | [Message List](/ui-kit/react-native/message-list) | Images, videos, audio and files that were downloaded while online are shown from the device when offline (with `mediaCaching` set to `AUTO`, the default). |
| Attachment uploads | [Message Composer](/ui-kit/react-native/message-composer) | A file that failed to upload can be retried, and staged attachments are restored when the user reopens the conversation. |

## Logging Out

The SDK deletes the cached data, cached media and any queued messages when the user logs out, and when a different user logs in. You don't need to clear anything yourself.

## Limitations

- The cache only holds what the user has loaded while online, plus the changes picked up when the device reconnects. A user who has never logged in online has nothing to show offline.
- Only sending messages works offline. Actions such as editing, deleting, reacting and pinning need a connection.
- Search reads from the server only, so it doesn't work while offline.
- There is no built-in offline banner and no "retry" action for a failed message. Use `CometChat.isOfflineEnabled()` and the SDK's [connection status](/sdk/react-native/connection-status) if you want to build your own.
