---
title: "Ongoing Call"
description: "In-call screen that joins the call session and renders the Calls SDK's call UI; also the activity the Push SDK opens when the user answers."
---

`CometChatOngoingCall` renders the active call: the Calls SDK's video tiles and controls (mute, camera, switch camera, end). `CometChatOngoingCallActivity` hosts it full-screen, supports picture-in-picture, and is the **answer activity** for push ringing: when the user answers an incoming call, the Push SDK opens it with the call in its intent and it joins the session.

---

## Where It Fits

Every call ends up here:

| Path | How the screen opens |
|------|----------------------|
| Incoming call answered | The Push SDK starts `CometChatOngoingCallActivity` (registered with `PNConfiguration.setAnswerActivity`). It reads the answered call from the intent and joins |
| Outgoing call answered | The [Outgoing Call](/ui-kit/android/outgoing-call) screen hands over once the callee joins: XML Views embed `CometChatOngoingCall` in the same activity, Compose launches `CometChatOngoingCallActivity` |
| Group call / meeting | [Call Buttons](/ui-kit/android/call-buttons) send a meeting message; tapping it launches the activity with `CallWorkFlow.MEETING` |
| Your own flow | `CometChatOngoingCallActivity.launchOngoingCallActivity(context, sessionId, callType)` or the component directly |

## Quick Start

### As the answer activity (incoming calls)

Register it once in the Push SDK configuration. No other code: the activity reads the session id and call type from the intent, asks for the microphone and camera, and calls `joinSession`.

```kotlin lines
PNConfiguration.Builder(APP_ID, REGION)
    .setProviderId(PROVIDER_ID)
    .setAnswerActivity(CometChatOngoingCallActivity::class.java)
    .build()
```

See [Calling Integration](/ui-kit/android/calling-integration) for the full setup.

### Launching it yourself

<Tabs>
<Tab title="Kotlin (XML Views)">

```kotlin lines
CometChatOngoingCallActivity.launchOngoingCallActivity(
```

### Embedding the component

Use the component directly when you host the call in your own screen.

<Tabs>
<Tab title="Kotlin (XML Views)">

```xml activity_call.xml lines
<com.cometchat.uikit.kotlin.presentation.ongoingcall.ui.CometChatOngoingCall
    android:id="@+id/ongoing_call"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />
```

```kotlin lines
val ongoingCall = findViewById<CometChatOngoingCall>(R.id.ongoing_call)
ongoingCall.setSessionId(sessionId)
ongoingCall.setCallType(CometChatConstants.CALL_TYPE_VIDEO)
ongoingCall.setCallWorkFlow(CallWorkFlow.DEFAULT)
ongoingCall.setSessionSettingsBuilder(CometChatCalls.SessionSettingsBuilder())
ongoingCall.startCall()
```

</Tab>
<Tab title="Jetpack Compose">

```kotlin lines
CometChatOngoingCall(
    sessionId = sessionId,
    callType = CometChatConstants.CALL_TYPE_VIDEO,
    callWorkFlow = CallWorkFlow.DEFAULT,
    onCallEnded = { finish() },
    onError = { e -> Log.e("Call", e.message ?: "") }
)
```

</Tab>
</Tabs>

Prerequisites: `CometChatUIKit.init()` with `setEnableCalling(true)`, a user logged in, and `RECORD_AUDIO` and `CAMERA` declared in the manifest.

## Actions and Events

### Callback Methods

#### `onCallEnded`

Fires when this device has left the session: the user tapped End, the other side hung up, the session timed out, or the connection closed. Close the screen here.

<Tabs>
<Tab title="Kotlin (XML Views)">

The hosting `CometChatOngoingCallActivity` finishes itself. When you embed the component, observe the ViewModel's events:

```kotlin lines
lifecycleScope.launch {
    ongoingCall.getViewModel()?.events?.collect { event ->
        if (event is OngoingCallEvent.CallEnded) finish()
    }
}
```

</Tab>
<Tab title="Jetpack Compose">

```kotlin lines
CometChatOngoingCall(
    sessionId = sessionId,
    callType = callType,
    onCallEnded = { finish() }
)
```

</Tab>
</Tabs>

#### `onError`

Fires when the session could not be joined (bad session id, no network, the Calls SDK not logged in) or the microphone permission is missing.

<Tabs>
<Tab title="Kotlin (XML Views)">

```kotlin lines
ongoingCall.setOnError { exception ->
    Log.e("OngoingCall", "Error: ${exception.message}")
}
```

</Tab>
<Tab title="Jetpack Compose">

```kotlin lines
CometChatOngoingCall(
    sessionId = sessionId,
    callType = callType,
    onError = { exception ->
        Log.e("OngoingCall", "Error: ${exception.message}")
    }
```

</Tab>

### ViewModel Events (`OngoingCallEvent`)

| Event | Fires when |
| --- | --- |
| `CallEnded` | This device left the session (End tapped, remote hang-up, connection closed) |
| `SessionTimeout` | The session timed out |
| `UserJoined(userId, isCurrentUser)` | A participant joined |
| `UserLeft(userId)` | A participant left |
| `Error(exception)` | Join failed or a permission is missing |

### Global UI Events (`CometChatEvents.callEvents`)

| Event | Fires when | Payload |
| --- | --- | --- |
| `CometChatCallEvent.CallEnded` | A 1:1 call ends on this device | `Call` (the answered call, when the screen was opened by the Push SDK) |

### SDK Events (Real-Time, Automatic)

| Calls SDK listener | Internal behavior |
| --- | --- |
| `SessionStatusListener.onSessionLeft` | Local clean-up, `CallEnded` |
| `SessionStatusListener.onSessionTimedOut` | `SessionTimeout`, screen ends |
| `SessionStatusListener.onConnectionClosed` | Screen ends, `CallEnded` (a join whose connection closed without a leave event) |
| `ParticipantEventListener.onParticipantJoined / Left` | `UserJoined` / `UserLeft` |
| `ButtonClickListener.onLeaveSessionButtonClicked` | The Calls SDK has already left; local clean-up only |

## Functionality

| Method (Kotlin XML) | Compose Parameter | Description |
| --- | --- | --- |
| `setSessionId(id)` | `sessionId` | Session to join (required) |
| `setCallType(type)` | `callType` | `CometChatConstants.CALL_TYPE_AUDIO` or `CALL_TYPE_VIDEO`; sets the session type |
| `setCallWorkFlow(flow)` | `callWorkFlow` | `DEFAULT` for 1:1 calls, `MEETING` for group calls |
| `setSessionSettingsBuilder(builder)` | `callSettingsBuilder` | Calls SDK `SessionSettingsBuilder` for layout, controls, audio mode. The component sets the session type on it |
| `startCall()` | automatic | Joins the session |
| `setOnError { }` | `onError` | Error callback |
| `setStyle(style)` | `style` | Container styling |
| `getViewModel()` | `viewModel` | Access to state and events |

## Hang-up and clean-up

Hanging up leaves the Calls SDK session with `CallSession.leave()`; nothing is sent to the Chat SDK. For a 1:1 call (`DEFAULT`) the UI Kit also clears its active-call state and emits `CometChatCallEvent.CallEnded` on `CometChatEvents.callEvents`. For a `MEETING` it only leaves and clears the meeting flag; the conference continues for the others.

`CometChatOngoingCallActivity` leaves the session when it is destroyed, but only its **own** session: after answering a second call over a live one, the Push SDK opens a fresh activity for the new session (the answer intent arrives in `onNewIntent` with `SINGLE_TOP`), and the old screen's clean-up does not touch it.

---

## Picture-in-Picture

`CometChatOngoingCallActivity` declares `supportsPictureInPicture` and enters PiP when the user leaves the screen during a call; the Calls SDK switches to its PiP layout (`enablePictureInPictureLayout` / `disablePictureInPictureLayout`). Dismissing the PiP window ends the call. Nothing to configure.

---

## Second call during a call

Handled by the Push SDK: the new call rings over the live one with "Answering ends your current call". Answer leaves the live session, prepares the new one and opens `CometChatOngoingCallActivity` again for it; Decline sends `busy` and keeps the current call.

```kotlin lines
CometChatOngoingCall(
```

The style covers the container around the call surface (background, progress indicator while joining, corner radius, stroke). The call UI itself (tiles, buttons, layouts) is the Calls SDK's and is configured through its `SessionSettingsBuilder`; see [Session Settings](/calls/android/session-settings) and [Call Layouts](/calls/android/call-layouts).

See [Component Styling](/ui-kit/android/component-styling) for the full reference.
