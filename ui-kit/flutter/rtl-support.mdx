## Overview

Languages such as Arabic are read right to left. In an RTL layout, the UI Kit mirrors every component: avatars, names, buttons, message bubbles, menus and sheets swap sides, and arrows point the other way.

Mirroring the layout doesn't mean flipping the content. The UI Kit keeps every piece of content readable:

* Each message line reads in its own direction, so an English line in an Arabic chat still reads left to right.
* Names, mentions and numbers keep their order inside the text around them.
* Audio and video players stay left to right, as they do in every RTL app.

## Layout Direction and Language

Layout direction and language are two separate settings:

| Setting | Decides | Set with |
| --- | --- | --- |
| Layout direction | Which side things sit on | `layoutDirection` |
| Language | Which strings are shown | The app's locale (see [Localize](/ui-kit/flutter/localize)) |

By default the layout direction follows the language: an app whose locale is Arabic is RTL. You can also set them apart, for example an English app set to RTL, or an Arabic app kept LTR.

## Turn On RTL

### Follow the app's language (default)

With the default value, `CometChatLayoutDirection.auto`, the UI Kit uses the direction the app is already in. `MaterialApp` makes the app RTL when its locale is an RTL language, so setting an Arabic locale is all you need:

<Tabs>
<Tab title="Dart">
```dart
MaterialApp(
  locale: const Locale('ar'),
  supportedLocales: CometChatLocalize.supportedLocales,
  localizationsDelegates: CometChatLocalize.localizationsDelegates,
  home: const YourHomeScreen(),
)
```
</Tab>
</Tabs>

See [Localize](/ui-kit/flutter/localize) for the full locale setup.

### Set it for the whole UI Kit

Pass `layoutDirection` in `UIKitSettings` to give every UI Kit component a fixed direction, whatever the language:

<Tabs>
<Tab title="Dart">
```dart
UIKitSettings uiKitSettings = (UIKitSettingsBuilder()
  ..appId = "your_appID"
  ..region = "your_region"
  ..authKey = "your_authKey"
  ..layoutDirection = CometChatLayoutDirection.rtl
).build();

CometChatUIKit.init(uiKitSettings: uiKitSettings);
```
</Tab>
</Tabs>

| Value | Result |
| --- | --- |
| `CometChatLayoutDirection.auto` | Follows the app's direction. This is the default, so apps that don't set it see no change. |
| `CometChatLayoutDirection.ltr` | Every UI Kit component is left to right. |
| `CometChatLayoutDirection.rtl` | Every UI Kit component is right to left. |

### Change it at runtime

Use `CometChatUIKit.setLayoutDirection` to change the direction while the app is running, for example from a settings screen. Read the current value with `CometChatUIKit.layoutDirection`.

<Tabs>
<Tab title="Dart">
```dart
CometChatUIKit.setLayoutDirection(CometChatLayoutDirection.rtl);

final current = CometChatUIKit.layoutDirection; // CometChatLayoutDirection.rtl
```
</Tab>
</Tabs>

<Note>
The new direction applies to screens opened after the change. A screen that is already open keeps its direction until it is reopened. `init()` sets the direction again from `UIKitSettings.layoutDirection`, so call `setLayoutDirection` after `init()`.
</Note>

## Set It Per Component

Every screen component takes a `layoutDirection` parameter. It overrides the global setting for that component and everything inside it:

<Tabs>
<Tab title="Dart">
```dart
// The whole kit is RTL, but this list stays LTR.
CometChatConversations(
  layoutDirection: CometChatLayoutDirection.ltr,
)
```
</Tab>
</Tabs>

Leave it `null` (or pass `auto`) to inherit the direction from the component around it, or from the global setting.

These components take `layoutDirection`:

| Chat | Calls | Messages |
| --- | --- | --- |
| [Conversations](/ui-kit/flutter/conversations) | [Call Buttons](/ui-kit/flutter/call-buttons) | [Message Header](/ui-kit/flutter/message-header) |
| [Users](/ui-kit/flutter/users) | [Call Logs](/ui-kit/flutter/call-logs) | [Message List](/ui-kit/flutter/message-list) |
| [Groups](/ui-kit/flutter/groups) | [Outgoing Call](/ui-kit/flutter/outgoing-call) | [Message Composer](/ui-kit/flutter/message-composer) |
| [Group Members](/ui-kit/flutter/group-members) | `CometChatOngoingCall` | [Threaded Messages Header](/ui-kit/flutter/threaded-messages-header) |
| [Search](/ui-kit/flutter/search) | | `CometChatMessageInformation` |
| [Notification Feed](/ui-kit/flutter/notification-feed) | | [Pinned Messages](/ui-kit/flutter/pinned-messages) |
| `CometChatAIAssistantChatHistory` | | [Saved Messages](/ui-kit/flutter/saved-messages) |

<Note>
On Android and iOS, incoming calls ring on the system call screen, which follows the phone's language. The deprecated `CometChatIncomingCall` screen (web only) has no `layoutDirection`; it follows the app's direction.
</Note>

## Which Setting Wins

When settings disagree, the first rule that gives a direction wins:

1. Audio and video players are always left to right.
2. The component's own `layoutDirection`, when it is `ltr` or `rtl`.
3. The nearest UI Kit component around it that has its own `layoutDirection`.
4. The global setting, when it is `ltr` or `rtl`.
5. The app's own direction, or left to right when there is none.

So wrapping a component in Flutter's `Directionality` changes it only while the global setting is `auto`. To force one component's direction, use its `layoutDirection` parameter.

## App Screens Outside the UI Kit

The UI Kit never changes your app's direction. With a global `ltr` or `rtl`, the UI Kit's components follow it but your own screens stay as they are. To give your own screens the same direction, set the direction in `MaterialApp.builder`:

<Tabs>
<Tab title="Dart">
```dart
MaterialApp(
  locale: locale,
  // ...
  builder: (context, child) {
    final direction = CometChatUIKit.layoutDirection.toTextDirection();
    if (direction == null) return child!; // auto: the locale decides
    return Directionality(textDirection: direction, child: child!);
  },
)
```
</Tab>
</Tabs>

With `auto` the locale decides for both your screens and the UI Kit, so nothing extra is needed.

## What Changes in RTL

### Layout

Everything that has a side moves to the other one: avatars, titles, subtitles, timestamps, unread badges, receipts, buttons, the composer's actions, message bubbles, menus, sheets, swipe actions and list indicators. Sent messages sit on the left and received messages on the right.

### Icons

| Icon | In RTL |
| --- | --- |
| Arrows that point along the reading direction: back, forward, send, reply, reply in thread, and call-direction arrows (incoming, outgoing, missed) | Flip on every platform |
| Video camera, copy, chat and sticker | Flip on Android and web; stay as drawn on iOS and macOS, following Apple's guidelines |
| Everything else: phone handset, microphone, attach, emoji, close, search, receipt ticks, pin, media controls, file types, logos | Stay as drawn |

Icons you pass into the UI Kit are drawn as you give them. For an arrow that should flip, use an icon with `matchTextDirection: true` (Material's arrow icons already have it).

### What doesn't mirror

* **Audio and video players**, including voice notes and the recorder: playback controls and progress bars stay left to right in every language.
* **Code blocks in AI assistant replies** stay left to right.

### Message text

* **Each line reads in its own direction.** The first letter of a line decides it: a line that starts with an English letter reads left to right, one that starts with an Arabic letter reads right to left. A line with no letters (only emoji or numbers) follows the bubble.
* **Names and mentions keep their place.** A user's name can't scramble the sentence around it, and a mention always reads `@name`, whatever the language of the name or the line.
* **Numbers and dates.** When the UI Kit's language is Arabic, dates, times and counts it formats use Arabic digits (٠١٢٣٤٥٦٧٨٩). An English app set to RTL keeps English dates and Western digits. Text you supply yourself, for example from a date formatter callback, is shown as given.
* **Text the UI Kit writes** keeps its language's order: in an English app set to RTL, "Delete this chat?" still ends with its question mark.

## Custom Views in RTL

Views you pass into the UI Kit (view slots, custom message templates, custom bubbles) are placed inside the component's direction, so they read `Directionality.of(context)` like any Flutter widget. Use direction-aware values so they mirror with the rest of the UI Kit:

| Instead of | Use |
| --- | --- |
| `EdgeInsets.only(left: 8)` | `EdgeInsetsDirectional.only(start: 8)` |
| `Alignment.centerLeft` | `AlignmentDirectional.centerStart` |
| `BorderRadius.only(topLeft: ...)` | `BorderRadiusDirectional.only(topStart: ...)` |
| `Positioned(left: 0)` | `PositionedDirectional(start: 0)` |
| `TextAlign.left` | `TextAlign.start` |

<Tabs>
<Tab title="Dart">
```dart
CometChatConversations(
  subtitleView: (context, conversation) => Padding(
    // Mirrors with the list: 8 px on the left in LTR, on the right in RTL.
    padding: const EdgeInsetsDirectional.only(start: 8),
    child: Text(
      conversation.lastMessage?.sender?.name ?? '',
      textAlign: TextAlign.start,
    ),
  ),
)
```
</Tab>
</Tabs>

`Row`, `ListTile` and other Flutter layouts already follow the direction.

## Languages

The UI Kit ships Arabic translations. For another RTL language, such as Hebrew, Persian or Urdu, add the language as described in [Adding New Language Support](/ui-kit/flutter/localize#adding-new-language-support). Once its locale is set, `auto` lays the UI Kit out right to left.
