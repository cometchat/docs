## Overview

This guide walks you through adding voice and video calling capabilities to your iOS application using the CometChat UI Kit.

<Info>
Make sure you've completed the [Getting Started](/ui-kit/ios/getting-started) guide before proceeding.
</Info>

## Add the Calls SDK

You can install the CometChat Calls SDK using either CocoaPods or Swift Package Manager.

<Note>
- CometChatCallsSDK supports iOS 13 and above
- CometChatCallsSDK supports Swift 5.0+
</Note>

### Option 1: CocoaPods

Open a terminal window, navigate to your project directory, and create a Podfile:

```ruby
$ pod init
```

Add the following lines to the Podfile:

```ruby
platform :ios, '15.1'
use_frameworks!

target 'YourApp' do
  pod 'CometChatUIKitSwift', '5.1.18'
  pod 'CometChatCallsSDK', '~> 5.0.4'
end
```

Install the dependencies:

```ruby
$ pod install
```

If you encounter issues, try:

```ruby
$ pod install --repo-update
```

To update to the latest version:

```ruby
$ pod update CometChatCallsSDK
```

<Tip>
Always open the `.xcworkspace` file after adding the dependencies.
</Tip>

### Option 2: Swift Package Manager

1. Go to File → Add Packages in Xcode
2. Add the CometChat Calls SDK repository:

```
https://github.com/cometchat/calls-sdk-ios.git
```

3. Select Version Rules, enter the version (e.g., 5.0.4), and click Next

<Info>
Make sure you have completed the Chat UI Kit integration before adding the Calls SDK.
</Info>

## Calls SDK Session

Adding the dependency activates the calling **UI**. Calling also needs a **Calls SDK session**, which is separate from your chat session.

From v5, the Calls SDK keeps its own session and authenticates its own requests — including the call-history request behind [CallLogs](/ui-kit/ios/call-logs). Without that session, CallLogs fails with *"Oops! Looks like something went wrong"*, even though chat and ringing work normally.

### Option 1 — Log in with the UI Kit (recommended)

`CometChatUIKit.login` starts the Calls SDK session for you, and `CometChatUIKit.logout` ends it. No extra calling code is needed.

<Tabs>
<Tab title="Swift">
```swift
CometChatUIKit.login(uid: "uid") { result in
  switch result {
  case .success(let user):
    // Chat and Calls are both authenticated.
    print("Login succeeded: \(user)")
  case .onError(let error):
    print("Login failed: \(error)")
  }
}
```
</Tab>
</Tabs>

<Warning>
If the Calls SDK login fails, `CometChatUIKit.login` reports a failure. Because the iOS UI Kit enables calling whenever the Calls SDK is linked, an app that links the SDK without using calling should opt out with `UIKitSettings.disableCalling()`.
</Warning>

### Option 2 — Log in with the Chat SDK directly

If your app authenticates with `CometChat.login` instead of `CometChatUIKit.login`, no Calls SDK session is created. Start and end it yourself, using the chat session's auth token.

<Tabs>
<Tab title="Swift">
```swift
// After CometChat.login succeeds:
CometChatCalls.login(authToken: CometChat.getUserAuthToken() ?? "") { callsUser in
  print("Calls SDK authenticated: \(callsUser)")
} onError: { error in
  print("Calls SDK login failed: \(error.errorDescription)")
}

// On sign-out, alongside CometChat.logout:
CometChatCalls.logout { _ in
  print("Calls SDK session ended")
} onError: { error in
  print("Calls SDK logout failed: \(error.errorDescription)")
}
```
</Tab>
</Tabs>

<Warning>
Log the Calls SDK out whenever you log the chat user out. A left-over session means the next user sees the previous user's call history.
</Warning>

<Note>
This option still requires initialising through `CometChatUIKit.init` or `CometChatUIKit.initFromSettings`, which is what initialises the Calls SDK. See [Methods](/ui-kit/ios/methods) for the UI Kit login and logout signatures, and [Calls Authentication](/calls/ios/authentication) for `CometChatCalls.login` and `CometChatCalls.logout`.
</Note>
