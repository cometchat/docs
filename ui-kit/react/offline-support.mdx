With offline support turned on, the UI Kit keeps showing the user's chats when the network drops. Conversations and messages load from a cache on the device first and are refreshed from the server when it is reachable, and messages sent while offline are delivered automatically once the connection returns.

The UI Kit builds on the [offline support in the JavaScript SDK](/sdk/javascript/offline-support). You turn it on in UI Kit settings; the components handle the rest.

## Enable Offline Support

Call `setOfflineConfig()` on the `UIKitSettingsBuilder` before `CometChatUIKit.init()`. Set `enabled: true` explicitly.

```tsx
import { CometChat } from "@cometchat/chat-sdk-javascript";
import { CometChatUIKit, UIKitSettingsBuilder } from "@cometchat/chat-uikit-react";

const settings = new UIKitSettingsBuilder()
  .setAppId("APP_ID")
  .setRegion("REGION")
  .setAuthKey("AUTH_KEY")
  .subscribePresenceForAllUsers()
  .setOfflineConfig({
    enabled: true,
    mediaCaching: CometChat.MediaCachingMode.AUTO,
  })
  .build();

CometChatUIKit.init(settings).then(() => {
  console.log("Initialization completed with offline support");
});
```

The UI Kit passes this object to the SDK unchanged, so it accepts every option in the [SDK configuration table](/sdk/javascript/offline-support#configuration-options) — the outbox size, media caching, encryption and so on. Always include `enabled: true`. If you don't call `setOfflineConfig()`, offline support stays off and the UI Kit works exactly as before.

Offline support is configured only through `CometChatUIKit.init()` with `UIKitSettings`. Initializing with `CometChatUIKit.initFromSettings()` doesn't turn it on.

<Warning>
  `setOfflineConfig()` needs a version of `@cometchat/chat-sdk-javascript`
  that includes offline support. The UI Kit calls the SDK's
  `AppSettingsBuilder.setOfflineConfig()` without checking for it, so with an
  older SDK `CometChatUIKit.init()` rejects with a `TypeError` instead of
  ignoring the setting.
</Warning>

<Note>
  Whether offline support is actually running can change after init — for
  example, CometChat can switch it off for your app from the server. The UI
  Kit checks `CometChat.isOfflineEnabled()` each time it needs to; do the same
  in your own code instead of reading back the value you configured.
</Note>

## What Changes in the Components

| Feature | Components | Behaviour |
| --- | --- | --- |
| Cached conversations | [Conversations](/ui-kit/react/components/conversations) | The list renders from the cache immediately, then updates with the server's list. Offline, the cached list stays on screen. |
| Cached messages | [Message List](/ui-kit/react/components/message-list) | A conversation opens with its cached messages, then updates with the server's page. |
| Sending while offline | [Message Composer](/ui-kit/react/components/message-composer), [Message List](/ui-kit/react/components/message-list) | A message sent offline from the composer appears in the list straight away with the sending (clock) indicator, and is queued. It is sent automatically when the connection returns, and its receipt then updates as usual. |
| Cached media | [Message List](/ui-kit/react/components/message-list) | Images, videos, audio and files that were downloaded while online are shown from the device when offline (with `mediaCaching` set to `AUTO`, the default). |
| Attachment uploads | [Message Composer](/ui-kit/react/components/message-composer#multi-attachment-staging-tray) | A file that failed to upload can be retried from the staging tray, and staged attachments are restored when the user reopens the conversation. |

## Logging Out

The SDK deletes the cached data, cached media and any queued messages when the user logs out, and when a different user logs in. You don't need to clear anything yourself.

## Limitations

- The cache only holds what the user has loaded while online, plus the changes picked up when the device reconnects. A user who has never logged in online has nothing to show offline.
- Only sending messages works offline. Actions such as editing, deleting, reacting and pinning need a connection.
- Search reads from the server only, so it doesn't work while offline.
- There is no built-in offline banner and no "retry" action for a failed message. A message that fails is never retried automatically. To build your own, use the SDK's [connection status](/sdk/javascript/connection-status) listener, and [`CometChat.getPendingMessages()` and `CometChat.retryMessage()`](/sdk/javascript/offline-support#failed-messages-and-retry).
