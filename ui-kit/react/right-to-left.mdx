## Overview

Every UI Kit component can lay out right to left. Lists, headers, message bubbles, the composer, menus and dialogs mirror, and directional icons such as the back arrow and send point the other way. Text keeps its own direction, so an English message in an Arabic chat still reads left to right.

Two settings control the layout direction:

| Setting | Values | Where you set it |
| --- | --- | --- |
| Global | `"auto"` (default), `"ltr"`, `"rtl"` | `UIKitSettingsBuilder.setLayoutDirection()` at init, or `layoutDirection` on `CometChatProvider` |
| Component | `"ltr"`, `"rtl"`. Unset: inherit | The `layoutDirection` prop on every public component |

A component takes its direction from the first of these that is set:

1. Its own `layoutDirection` prop.
2. The `layoutDirection` of the nearest kit component it sits inside.
3. The global setting, when it is `"ltr"` or `"rtl"`.
4. Your app's direction: the `dir` of `<html>`, or of an element the component is inside (global `"auto"`).

The kit writes the result as `dir` on the component's root element. Base components (avatar, badge, button, list item, date, receipts, popover, ...) have no setting of their own: they follow the component they sit in, and used on their own they follow the global setting. Audio and video players are the one exception: they always lay out left to right (see [Audio and Video Players](#audio-and-video-players-stay-left-to-right)).

An app that sets no direction and has no `dir="rtl"` on its page lays out left to right, as before.

## Follow Your App's Direction (Default)

With the default, `"auto"`, the kit follows your app. Set `dir` on `<html>` and every component lays out to match. This is the recommended setup for an app that is itself right to left.

```html
<html lang="ar" dir="rtl">
```

The kit never writes `<html dir>`. If your app switches language at runtime, set the page's direction from the language yourself. Direction and language are separate settings: `locale` picks the kit's strings, `dir` picks the layout.

```tsx title="src/App.tsx"
import { useLayoutEffect, useState } from "react";
import { CometChatLocalize, CometChatProvider } from "@cometchat/chat-uikit-react";

function App() {
  const [language, setLanguage] = useState("ar");

  // Your app sets the page's language and direction, not the kit.
  // useLayoutEffect: the page has its direction before the first paint.
  useLayoutEffect(() => {
    document.documentElement.lang = language;
    document.documentElement.dir = CometChatLocalize.getDirection(language); // "rtl" for "ar"
  }, [language]);

  return (
    <CometChatProvider locale={language}>
      <MyChatApp />
    </CometChatProvider>
  );
}
```

`CometChatLocalize.getDirection()` only reports a direction; it changes nothing. It returns `"rtl"` for Arabic (`ar`), Hebrew (`he`), Persian (`fa`), Urdu (`ur`) and other languages written in a right-to-left script, in any region (`ar-SA`, `ar-EG`, ...), and `"ltr"` otherwise. Called with no argument, it uses the kit's current language.

## Set the Direction for the Whole Kit

To lay out every kit component in one direction whatever your app's direction, set it when you initialize the kit:

```tsx title="src/main.tsx"
import { CometChatUIKit, UIKitSettingsBuilder } from "@cometchat/chat-uikit-react";

const settings = new UIKitSettingsBuilder()
  .setAppId("YOUR_APP_ID")
  .setRegion("YOUR_REGION")
  .setAuthKey("YOUR_AUTH_KEY")
  .subscribePresenceForAllUsers()
  .setLayoutDirection("rtl") // "auto" (default) | "ltr" | "rtl"
  .build();

CometChatUIKit.init(settings).then(() => {
  // Log in and render your app
});
```

Or pass it to the provider, next to `locale`:

```tsx
<CometChatProvider locale="ar" layoutDirection="rtl">
  <MyChatApp />
</CometChatProvider>
```

These are the same setting, so use one of them. When `CometChatProvider` has a `layoutDirection` prop, it takes precedence over the init setting, including when it is `"auto"`: leave the prop out to keep the init setting.

Neither changes `<html dir>`: the rest of your page keeps its own direction.

### Changing It Later

```tsx
import { CometChatUIKit } from "@cometchat/chat-uikit-react";

CometChatUIKit.setLayoutDirection("ltr");
```

The new direction applies to components mounted afterwards. Components already on screen keep their direction until they mount again, for example when the user reopens the screen.

<Note>
Inside a `CometChatProvider` that has a `layoutDirection` prop, change the prop instead: it wins over `setLayoutDirection()`, and because it is a React prop, components already on screen update straight away.
</Note>

## Set the Direction of One Component

Every public component takes a `layoutDirection` prop, `"ltr"` or `"rtl"`. It wins over the global setting, and the components inside it, including the menus, popovers and dialogs it opens, follow it unless they set their own:

```tsx
<CometChatMessageList user={user} layoutDirection="ltr" />

<CometChatConversations layoutDirection="rtl" />
```

Leave it unset to inherit. Changing the prop updates the component at once.

<Warning>
When the global setting is `"ltr"` or `"rtl"`, wrapping a component in an element with its own `dir` does **not** change the component's direction:

```tsx
// With setLayoutDirection("rtl"), this list still lays out right to left
<div dir="ltr">
  <CometChatConversations />
</div>
```

The kit applies the global setting on each component's root element, so it wins over the wrapper. Use the component's prop instead: `<CometChatConversations layoutDirection="ltr" />`. A `dir` wrapper only works while the global setting is `"auto"`.
</Warning>

## Arabic

Arabic (`ar`) is one of the kit's built-in languages; regional tags such as `ar-SA` and `ar-EG` use it too. Pass it to the provider:

```tsx
<CometChatProvider locale="ar">
  <MyChatApp />
</CometChatProvider>
```

The language doesn't change the layout. With the global setting `"auto"`, the kit lays out right to left when your app does, so set `<html dir="rtl">` from the language, as in the example above. To lay out the kit right to left without changing your page, add `layoutDirection="rtl"` to the provider as well.

In Arabic, dates and times use Arabic-Indic digits (٠١٢٣٤٥٦٧٨٩). A regional tag such as `ar-MA` uses that region's own digits. To change any Arabic string, override it as you would for any other language: see [Adding Custom Translations](/ui-kit/react/localization#adding-custom-translations).

## What Mirrors

In a right-to-left layout:

- Lists, headers, the composer and toolbars run right to left. Outgoing messages move to the left and incoming messages to the right.
- Menus, popovers, dialogs, sheets and toasts take the direction of the component that opens them, and stay on screen near both edges.
- The left and right arrow keys follow the layout: in a right-to-left list, the left arrow moves to the next item.
- Directional icons mirror. Icons that don't point a direction stay as drawn:

| Icons | In a right-to-left layout |
| --- | --- |
| Back and forward arrows, sideways chevrons, send, reply, call-direction arrows (incoming, outgoing, missed), video camera, copy, chat, sticker | Mirror |
| Phone handset, microphone, attach, emoji, close, search, sent/delivered/read ticks, pin, media controls (play, pause), file types, logos | Stay as drawn |

### Audio and Video Players Stay Left to Right

Audio and video players, including voice notes, always lay out left to right, whatever the setting: the timeline and play controls read the way the media plays, as they do in other apps. The bubble around the player still follows the layout.

---

## Text Direction

Layout direction and text direction are separate:

- **Message text keeps its own direction.** An English message in a right-to-left chat reads left to right, and an Arabic message reads right to left even in a left-to-right app. Conversation previews and subtitles do the same, and names, mentions and file names keep their own order in mixed Arabic and English text.
- **Typed text** in the composer and other text fields takes the direction of what is typed.
- **Code blocks, URLs and email addresses** stay left to right.
- **The kit's own labels** (empty and error states, dialog text, placeholders) read in the UI language's direction, so an English label in a right-to-left layout keeps its punctuation at the end. Their position still follows the layout.
- **Digits:** in Arabic, dates and times use Arabic-Indic digits.

## Custom Views, Slots and CSS

The kit's stylesheets use logical properties, so they mirror on their own. Views you pass to a component (custom item, subtitle or header views) render inside its root element and inherit its direction; write them and your CSS overrides so they mirror too.

**Use logical properties.** Physical ones still apply in a left-to-right layout exactly as before, but don't mirror.

| Instead of | Use |
| --- | --- |
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` |
| `padding-left` / `padding-right` | `padding-inline-start` / `padding-inline-end` |
| `left` / `right` | `inset-inline-start` / `inset-inline-end` |
| `border-left` / `border-right` | `border-inline-start` / `border-inline-end` |
| `text-align: left` / `right` | `text-align: start` / `end` |

**Style by direction with `:dir(rtl)`, not `[dir="rtl"] .x`.** A component set to `"ltr"` on a right-to-left page is still inside `<html dir="rtl">`, so an attribute selector matches it wrongly. `:dir()` matches the direction the element actually lays out in.

```css
/* Matches the direction the icon actually lays out in */
.my-forward-icon:dir(rtl) {
  transform: scaleX(-1);
}

/* Avoid: also matches inside a component set to "ltr" on an RTL page */
[dir="rtl"] .my-forward-icon {
  transform: scaleX(-1);
}
```

For a directional icon in your own view, you can also add the kit's `cometchat-icon--mirror` class, which flips it in a right-to-left layout. `:dir()` needs Chrome 120, Safari 16.4, Firefox 49 or later.

**Read the direction from the element** in code, not from `<html>` or the global setting:

```tsx
const isRtl = getComputedStyle(element).direction === "rtl";
```

**Pass the direction to overlays you open yourself.** The kit's own menus and dialogs carry the direction of the component that opens them. A menu or popover you render through a portal into `document.body` leaves that component's DOM, so copy the direction from the element it opens from:

```tsx
import { useState } from "react";
import type { MouseEvent } from "react";
import { createPortal } from "react-dom";

function MoreButton() {
  const [menuDir, setMenuDir] = useState<string | null>(null);

  function openMenu(event: MouseEvent<HTMLButtonElement>) {
    // The direction the button lays out in: from the kit setting, a wrapper or <html dir>.
    setMenuDir(getComputedStyle(event.currentTarget).direction);
  }

  return (
    <>
      <button onClick={openMenu}>More</button>
      {menuDir &&
        createPortal(
          <div dir={menuDir} className="my-menu">
            {/* menu items */}
          </div>,
          document.body
        )}
    </>
  );
}
```

## Common Scenarios

| You want | Global setting | Component setting |
| --- | --- | --- |
| Your app is already in Arabic and right to left | `"auto"` (the default) and `<html dir="rtl">` | None |
| An English app, with the chat in Arabic and right to left | `"rtl"`, plus `locale="ar"` on `CometChatProvider` | None |
| Everything right to left except one component | `"rtl"` | `"ltr"` on that component |
| A right-to-left app with one component left to right | `"auto"` | `"ltr"` on that component |
| Only the chat screen right to left, in a left-to-right app | `"auto"` | `"rtl"` on the screen's outer component |

In the last case, the components inside the outer one follow it. For components side by side, such as a header, message list and composer, set the prop on each, or wrap them in `<div dir="rtl">`: a wrapper works because the global setting is `"auto"`.
