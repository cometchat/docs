The **UI Kit Builder** simplifies integrating CometChat's UI Kit into your React Router application — quickly set up chat, customize UI elements, and add features without extensive coding.

<Frame>
  <img src="/images/uikit-builder-preview.png" />
</Frame>

<Note>
  The UI Kit Builder exports a **React** code package. There is no separate React
  Router export — this guide covers dropping that package into a React Router
  project, whether it renders entirely in the browser or uses framework mode with
  server rendering.
</Note>

## **Complete Integration Workflow**

1. **Design Your Chat Experience** - Use the **UI Kit Builder** to customize layouts, features, and styling.
2. **Review and Export** - Review which features will be enabled in your Dashboard, toggle them on/off, and download the generated code package.
3. **Preview Customizations** - Optionally, preview the chat experience before integrating it into your project.
4. **Integration** - Integrate into your existing application.
5. **Customize Further** - Explore advanced customization options to tailor the chat experience.

---

## **Requirements**

The exported app targets **[React UI Kit v7](/ui-kit/react/overview)**:

| | |
| --- | --- |
| React | 18 or 19 |
| React Router | v6 or v7 — either a browser-only app (`react-router-dom` in Vite) or v7 framework mode |
| UI Kit | `@cometchat/chat-uikit-react` v7 |
| TypeScript | `jsx: "react-jsx"` and `resolveJsonModule: true` — see [Troubleshooting](#troubleshooting) |

If your app uses React Router v7 **framework mode**, which server-renders by default, read
[Framework mode and SSR](#framework-mode-and-ssr) before Step 3 — the chat has to be kept off the
server.

## **Integrate into Your Project**

Follow these steps to integrate the exported app into your existing React Router project.

### **Step 1: Install Dependencies**

```bash
npm install @cometchat/chat-uikit-react@^7.2.0 @cometchat/chat-sdk-javascript@^4.2.0 @cometchat/calls-sdk-javascript@^5.0.3
```

### **Step 2: Copy Two Folders**

Copy **both** of these from the exported app into your project's `src` directory:

| Folder | What it is |
| --- | --- |
| `src/CometChat` | The CometChat sample app. Treat it as vendored — it is replaced wholesale on every UI Kit release, so edits here are lost. |
| `src/builder` | Your builder settings, theming and localization. This is the part you own and customize. |

Both are required: `src/CometChat` reads its configuration from `src/builder`.

<Warning>
  Copying only `src/CometChat` leaves the app without its settings, theme and
  localization. The split is deliberate: because your customizations sit outside
  the vendored folder, a later re-export means copying `src/CometChat` alone.
</Warning>

### **Step 3: Initialize CometChat UI Kit**

Initialization also wires up `SettingsProvider`, which feeds your builder settings into the app. Select your setup:

<Tabs>
<Tab title="Vite">

Open `src/main.tsx` and update it:

```tsx
import { createRoot } from "react-dom/client";
import { CometChatUIKit, UIKitSettingsBuilder } from "@cometchat/chat-uikit-react";
import App from "./App";
import "./builder/shell.css"; // Gives the chat UI its full height — required.
import { SettingsProvider } from "./CometChat/config/SettingsContext";
import { builderSettings } from "./builder/builderSettings";
import { setupLocalization } from "./builder/localization";

export const COMETCHAT_CONSTANTS = {
  APP_ID: "", // Replace with your App ID
  REGION: "", // Replace with your App Region
  AUTH_KEY: "", // Replace with your Auth Key
};

const uiKitSettings = new UIKitSettingsBuilder()
  .setAppId(COMETCHAT_CONSTANTS.APP_ID)
  .setRegion(COMETCHAT_CONSTANTS.REGION)
  .setAuthKey(COMETCHAT_CONSTANTS.AUTH_KEY)
  .subscribePresenceForAllUsers()
  // Without this the call buttons do not render at all.
  .setCallingEnabled(true)
  .build();

const root = createRoot(document.getElementById("root")!);

Promise.resolve(CometChatUIKit.init(uiKitSettings))
  .then(() => {
    setupLocalization();
    root.render(
      <SettingsProvider settings={builderSettings}>
        <App />
      </SettingsProvider>
    );
  })
  .catch((error) => console.error("CometChat UI Kit failed to initialise", error));
```

<Note>
  Replacing `main.tsx` also removes the Vite template's `import "./index.css"`.
  Keep it removed, or delete its `#root` rules (fixed width, centering,
  `text-align: center`) — they offset the chat UI and make it overflow the page.
</Note>

</Tab>

<Tab title="Create React App">

Open `src/index.tsx` and update it:

```tsx
import ReactDOM from "react-dom/client";
import { CometChatUIKit, UIKitSettingsBuilder } from "@cometchat/chat-uikit-react";
import App from "./App";
import "./builder/shell.css"; // Gives the chat UI its full height — required.
import { SettingsProvider } from "./CometChat/config/SettingsContext";
import { builderSettings } from "./builder/builderSettings";
import { setupLocalization } from "./builder/localization";

export const COMETCHAT_CONSTANTS = {
  APP_ID: "", // Replace with your App ID
  REGION: "", // Replace with your App Region
  AUTH_KEY: "", // Replace with your Auth Key
};

const uiKitSettings = new UIKitSettingsBuilder()
  .setAppId(COMETCHAT_CONSTANTS.APP_ID)
  .setRegion(COMETCHAT_CONSTANTS.REGION)
  .setAuthKey(COMETCHAT_CONSTANTS.AUTH_KEY)
  .subscribePresenceForAllUsers()
  .setCallingEnabled(true)
  .build();

const root = ReactDOM.createRoot(document.getElementById("root") as HTMLElement);

Promise.resolve(CometChatUIKit.init(uiKitSettings))
  .then(() => {
    setupLocalization();
    root.render(
      <SettingsProvider settings={builderSettings}>
        <App />
      </SettingsProvider>
    );
  })
  .catch((error) => console.error("CometChat UI Kit failed to initialise", error));
```

</Tab>
</Tabs>

<Info>
  Your app credentials (`APP_ID`, `AUTH_KEY`, `REGION`) are prepopulated in the exported code. If you need different credentials, find them in the Credentials block of your app's [Overview section](https://app.cometchat.com) on the CometChat Dashboard.
</Info>

<Note>
  **Upgrading from v6?** `CometChatProvider` no longer comes from a local
  `CometChat/context/CometChatContext`, `setupLocalization` has moved to
  `builder/localization`, and `CometChat/utils/utils` and
  `CometChat/CometChatApp` no longer exist. The code above is the v7 replacement
  for all four.
</Note>

**Session storage.** To use session storage instead of the default local storage, configure it during initialization — see the [Setting Session Storage Mode guide](/ui-kit/react/methods#setting-session-storage-mode).

### **Step 4: User Authentication**

CometChat uses a UID (User ID) to identify each user. After initialization, authenticate users to enable chat functionality.

You can either:

1. **Create new users** on the **[CometChat Dashboard](https://app.cometchat.com)**, with a **[CometChat SDK method](/ui-kit/react/methods)**, or **[via the API](https://www.cometchat.com/docs/rest-api/users/create)**.
2. **Use pre-generated test users**: `cometchat-uid-1` through `cometchat-uid-5`.

The app shell in Step 5 already handles this for you: it renders `CometChatLogin` until someone is logged in, and listens for SDK login and logout events afterwards. Use the methods below when you want to log users in from your own flow instead.

<Tabs>
<Tab title="Auth Key (prototyping)">

```tsx
import { CometChatUIKit } from "@cometchat/chat-uikit-react";

const user = await CometChatUIKit.login("cometchat-uid-1");
console.log("Logged in:", user);
```

</Tab>

<Tab title="Auth Token (production)">

```tsx
import { CometChatUIKit } from "@cometchat/chat-uikit-react";

// Fetch the auth token from your backend, then:
const user = await CometChatUIKit.loginWithAuthToken(authToken);
console.log("Logged in:", user);
```

</Tab>
</Tabs>

`CometChatUIKit.getLoggedInUser()` returns the current user synchronously, or `null` when nobody is logged in.

<Note>
  **Auth Key vs Auth Token**

  Auth Key is perfect for prototyping. For production apps, switch to Auth Token for secure authentication. See [Authentication and User Management](/fundamentals/user-auth) for details.
</Note>

### **Step 5: Render the App Shell**

v7 has no `CometChatApp` component. `src/App.tsx` is the integration point, and it is yours to edit:

```tsx
import "./CometChat/styles/App.css";
import { useEffect, useState } from "react";
import { CometChat } from "@cometchat/chat-sdk-javascript";
import { CometChatProvider, CometChatUIKit } from "@cometchat/chat-uikit-react";
import { CometChatHome } from "./CometChat/components/CometChatHome/CometChatHome";
import CometChatLogin from "./CometChat/components/CometChatLogin/CometChatLogin";
import { AppContextProvider } from "./CometChat/context/AppContext";
import { useSettings } from "./CometChat/config/SettingsContext";
import useSystemColorScheme from "./builder/customHooks";
import { useBuilderTheme } from "./builder/useBuilderTheme";

function App() {
  const [loggedInUser, setLoggedInUser] = useState<CometChat.User | null>(null);
  const { style } = useSettings();
  const systemTheme = useSystemColorScheme();

  // The UI Kit accepts only 'light' | 'dark' — resolving 'system' is the consumer's job.
  const theme: "light" | "dark" =
    style.theme === "light" || style.theme === "dark" ? style.theme : systemTheme;

  useBuilderTheme(style, theme);

  useEffect(() => {
    setLoggedInUser(CometChatUIKit.getLoggedInUser() ?? null);

    CometChat.addLoginListener(
      "app-login-listener",
      new CometChat.LoginListener({
        loginSuccess: (user: CometChat.User) => setLoggedInUser(user),
        logoutSuccess: () => setLoggedInUser(null),
      })
    );

    return () => CometChat.removeLoginListener("app-login-listener");
  }, []);

  const handleLogout = async () => {
    await CometChatUIKit.logout();
    setLoggedInUser(null);
  };

  return (
    /* The chat UI fills its parent, so give it explicit dimensions. */
    <div className="App" style={{ width: "100vw", height: "100dvh" }}>
      <CometChatProvider theme={theme} locale="en-us">
        <AppContextProvider>
          {loggedInUser ? (
            <CometChatHome loggedInUser={loggedInUser} onLogout={handleLogout} />
          ) : (
            <CometChatLogin onLoginSuccess={setLoggedInUser} />
          )}
        </AppContextProvider>
      </CometChatProvider>
    </div>
  );
}

export default App;
```

**Sizing.** `.App` sets the size — change its `style` to fit the chat into part of your page. The `.cometchat` element that `CometChatProvider` renders inside it has no height of its own; `src/builder/shell.css`, imported in Step 3, makes it fill `.App`. If you don't import that file, add this to your own CSS — without it the chat shrinks to its content and the message composer is pushed off-screen:

```css
.App > .cometchat {
  height: 100%;
}
```

### **Rendering the chat at a route**

`App` above is the whole chat experience. In a React Router app you usually want it on one route
rather than at the root, so render it as that route's element:

```tsx
import { createBrowserRouter, RouterProvider } from "react-router-dom";
import App from "./App";
import Home from "./Home";

const router = createBrowserRouter([
  { path: "/", element: <Home /> },
  { path: "/chat", element: <App /> },
]);

export default function Root() {
  return <RouterProvider router={router} />;
}
```

Keep initialization where Step 3 put it — at your entry file, outside the router — so the UI Kit is
ready before any route renders, and is not re-initialized on navigation.

<Note>
  The chat fills its parent, so the route's layout needs a height. If your route
  renders inside a shell with a header or sidebar, give the chat's container a
  height (for example `calc(100dvh - 64px)`) rather than the `100dvh` used above.
</Note>

### **Step 6: Customize Through Settings**

Layout and feature choices live in `src/builder/cometchat-builder-settings.json`, which the dashboard writes at export time and which you can edit by hand afterwards. Anything the file omits falls back to a default, so partial files are safe.

| Setting | Effect |
| --- | --- |
| `layout.withSideBar` | `false` renders a single chat pane with no conversations list. |
| `layout.chatType` | `user` or `group` — which chat opens when there is no sidebar. |
| `style.theme` | `light`, `dark`, or `system`. |
| `style.color`, `style.typography` | Brand color, text colors and font, applied by `useBuilderTheme`. |
| `chatFeatures.*`, `callFeatures.*` | Per-feature toggles, mapped to UI Kit props by `buildFeatureProps`. |

Group action messages (joins, leaves, kicks, bans) are the exception: there is no settings key for them. They are on by default, and the only way to change that from code is the `showGroupActionMessages` prop on `CometChatHome` — the same prop v6 had on `CometChatApp`. Whether they are generated at all is an app-level choice: **Chat > Settings > Include Group Actions** in the dashboard.

Every setting is described in [UI Kit Builder Settings](/chat-builder/react-router/builder-settings).

## **Framework mode and SSR**

React Router v7's framework mode server-renders by default. The CometChat UI Kit and the copied
`CometChat` folder touch browser APIs (`window`, `document`, WebSockets) as soon as they load, so
rendering them on the server fails with `window is not defined`. Pick whichever fits your app.

### Option A — turn server rendering off

If the app does not need SSR, set it off once in `react-router.config.ts`:

```ts
import type { Config } from "@react-router/dev/config";

export default {
  ssr: false,
} satisfies Config;
```

Your app now builds as an SPA and the integration steps above apply unchanged.

### Option B — keep SSR, render the chat only in the browser

Keep server rendering for the rest of the app and load the chat after mount. Because the import
itself must not run on the server, it has to be lazy — not a top-level `import`:

```tsx
import { lazy, Suspense, useEffect, useState } from "react";

const App = lazy(() => import("../App")); // the shell from Step 5

export default function ChatRoute() {
  const [mounted, setMounted] = useState(false);

  // Effects never run on the server, so this flips only in the browser.
  useEffect(() => setMounted(true), []);

  if (!mounted) return null; // or your own loading state

  return (
    <Suspense fallback={null}>
      <App />
    </Suspense>
  );
}
```

Initialization (Step 3) must move into that client-only boundary too — put it in a `useEffect` in
the same component, and render the shell once it resolves. The
[Next.js guide](/chat-builder/nextjs/integration) shows that shape in full; the only difference is
that Next.js has `dynamic(..., { ssr: false })` where React Router uses `lazy` plus the mounted
guard.

<Warning>
  A top-level `import` of the chat anywhere a server-rendered route can reach
  defeats both options — the module loads during SSR before your guard runs. Keep
  every path to `CometChat/` and `builder/` behind the lazy import.
</Warning>

## **Troubleshooting**

**TypeScript configuration.** Check that your TypeScript config includes both of these. In a Vite project that is `tsconfig.app.json`, not the root `tsconfig.json`. New Vite and Create React App projects already have them:

```json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "resolveJsonModule": true
  }
}
```

`resolveJsonModule` is required — `builderSettings` imports the settings JSON directly. Restart your dev server after changing it.

**The chat renders but has no height.** `src/builder/shell.css` is not imported, or your own CSS overrides it. See the sizing note in Step 5.

**Call buttons do nothing.** `setCallingEnabled(true)` is missing from the initialization in Step 3, or `@cometchat/calls-sdk-javascript` is not installed.

**The chat is off-centre or overflows the page.** The Vite template's `index.css` is still imported; its `#root` rules fight the chat's layout. See the note in Step 3.

**`window is not defined` during build or dev.** You are in framework mode and something imports the chat on the server — see [Framework mode and SSR](#framework-mode-and-ssr).
