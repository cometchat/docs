<Note>
  **This is the recommended way to add chat push notifications to an iOS app.**
  `CometChatPushNotifications` handles APNs token registration, foreground presentation,
  notification taps, quick reply, delivery and campaign receipts, and badge counts. It works with
  **or without** the UI Kit.

  This page covers **chat notifications only**. For incoming calls (PushKit + CallKit), see
  [Calls: VoIP Calling](/calls/ios/voip-calling). If you would rather wire
  APNs yourself, see [iOS APNs Push Notifications](/notifications/ios-apns-push-notifications).
</Note>

## Install

The package ships three products. A chat app adds two of them:

| Product | Add it | Contains |
|---|---|---|
| `CometChatPushNotificationsSwift` (Core) | Always | Permission, APNs registration, foreground presentation, taps, badge, campaign receipts |
| `CometChatPushNotificationsChat` (Chat) | For chat notifications | Delivery receipts, quick reply, typed "open this chat" navigation, the Notification Service Extension base class |
| `CometChatPushNotificationsCalls` (Calls) | Only for incoming calls | See [VoIP Calling](/calls/ios/voip-calling) |

<Tabs>
<Tab title="Swift Package Manager">
In Xcode, **File → Add Package Dependencies** and add:

```
https://github.com/cometchat/push-notifications-sdk-ios
```

Pick version **2.0.0** or later, and add **`CometChatPushNotificationsSwift`** and
**`CometChatPushNotificationsChat`** to your app target.
</Tab>
<Tab title="CocoaPods">
```ruby
platform :ios, '15.1'

target 'YourApp' do
  use_frameworks!
  pod 'CometChatPushNotificationsSwift', '2.0.0'
  pod 'CometChatPushNotificationsChat', '2.0.0'
end
```

Then `pod install`. The Chat pod pulls `CometChatSDK` automatically.
</Tab>
</Tabs>

<Note>
  Each product is its own module. Import **`CometChatPushNotificationsSwift`** for the main
  `CometChatPushNotifications` class and **`CometChatPushNotificationsChat`** for the chat delegate
  and the extension base class.

## Before you start

1. In the **CometChat dashboard**, enable Push Notifications, add an **APNs Device** provider, and
   copy its **Provider ID**. If the same app also receives calls, use a token-based (`.p8`)
   provider — one `.p8` key serves both the device token and the VoIP token.
2. In Xcode, add these capabilities to your app target:
   - **Push Notifications**
   - **Background Modes** → **Remote notifications**

## 1. Initialize

Call `initialize` from `application(_:didFinishLaunchingWithOptions:)`:

```swift
import CometChatPushNotificationsSwift

func application(_ application: UIApplication,
                 didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
    CometChatPushNotifications.shared.delegate = pushRouter   // see step 3
    CometChatPushNotifications.shared.initialize(config: PNConfiguration(
        appId: "YOUR_APP_ID",
        region: "YOUR_REGION",
        providerId: "YOUR_PROVIDER_ID",
        extensionGroupID: "group.com.yourcompany.yourapp"   // optional — see the extension section
    ))
    return true
}
```

That call:

- requests notification permission and registers for remote notifications,
- installs the Chat product,
- takes over `UNUserNotificationCenter.delegate` (foreground banners and taps),
- registers the APNs token on every Chat SDK login.

`appId` and `region` are required. `providerId` is required to register tokens.

<Note>
  You do **not** call `CometChatNotifications.registerPushToken(...)` yourself. The SDK registers
  the token whenever a user logs in to the Chat SDK. To register it under an auth token you mint
  yourself, pass `authToken` in the configuration.
</Note>

<Tip>
  If your app already has a `UNUserNotificationCenterDelegate`, set it **after** `initialize` and
  forward to `handleWillPresentNotification(_:completionHandler:)` and
  `handleNotificationResponse(_:completionHandler:)`. Otherwise taps, quick reply and foreground
  banners stop working.
</Tip>

## 2. Forward the APNs token

In your `AppDelegate`:

```swift
func application(_ application: UIApplication,
                 didRegisterForRemoteNotificationsWithDeviceToken deviceToken: Data) {
    CometChatPushNotifications.shared.registerDeviceToken(deviceToken)
    // Optional result:
    // CometChatPushNotifications.shared.registerDeviceToken(deviceToken) { result in ... }   // PNResult<String>
}

// Recommended — surfaces entitlement and provisioning problems during development.
func application(_ application: UIApplication,
                 didFailToRegisterForRemoteNotificationsWithError error: Error) {
    CometChatPushNotifications.shared.handleRegistrationFailure(error)
}

// Optional — silent/background pushes (campaign receipts, badge updates).
func application(_ application: UIApplication,
                 didReceiveRemoteNotification userInfo: [AnyHashable: Any],
                 fetchCompletionHandler completionHandler: @escaping (UIBackgroundFetchResult) -> Void) {
    CometChatPushNotifications.shared.handleBackgroundNotification(userInfo: userInfo)
    completionHandler(.newData)
}
```

<Note>
  The token can arrive before the user logs in. The SDK caches it and registers it on the next
  login, so the order does not matter.
</Note>

## 3. Implement the delegate

One object receives every event. Adopt `CometChatPushNotificationsChatDelegate` for typed chat
navigation. Every method is optional; implement only what you need. The delegate is an
Objective-C protocol, so the object must inherit from `NSObject`.

```swift
import CometChatSDK
import CometChatPushNotificationsSwift
import CometChatPushNotificationsChat

final class PushRouter: NSObject, CometChatPushNotificationsChatDelegate {

    // MARK: Notification taps
    func navigateToChat(for user: User)   { /* push your 1-1 chat screen */ }
    func navigateToChat(for group: Group) { /* push your group chat screen */ }
    func navigateToNotificationsFeed()    { /* campaign push tapped — open your notifications screen */ }
    func navigateToDefaultScreen()        { /* fallback destination */ }

    // A tap the SDK did not recognise. The raw payload is in info.rawPayload.
    func didTapNotification(_ info: CometChatNotificationInfo) { }

    // MARK: Observability
    func onPushTokenRegistered(platform: CometChatPushTokenPlatform) { }
    func onPushTokenRegistrationFailed(platform: CometChatPushTokenPlatform, error: PNError) {
        // Fires for automatic registrations too — the fastest way to catch a wrong Provider ID.
    }
}
```

If a tap is not routed to `navigateToChat` or `navigateToNotificationsFeed`, the SDK calls
`didTapNotification(_:)`. If you have not implemented it, the SDK calls
`navigateToDefaultScreen()`.

| Type | Values |
|---|---|
| `CometChatPushTokenPlatform` | `.apns` · `.fcm` · `.voip` |
| `PNError.Code` | `.notInitialised` · `.notLoggedIn` · `.providerRequired` · `.productNotInstalled` · `.serverError` · `.networkError` |

## 4. Unregister on logout

Unregistering needs the user's auth token. Call `unregisterTokens` and **wait for it to finish
before** you log out:

```swift
CometChatPushNotifications.shared.unregisterTokens { _ in
    CometChat.logout(onSuccess: { _ in /* ... */ }, onError: { _ in /* ... */ })
}
```

If you log out first, the unregister request has no auth token and fails, so the device can keep
receiving the previous user's notifications.

## Notification Service Extension

Adds delivery receipts, sender avatars, campaign images and markdown-free notification text.

<Steps>
<Step title="Add the target">
  **File → New → Target → Notification Service Extension.**
</Step>
<Step title="Share an App Group">
  Add the same App Group (e.g. `group.com.yourcompany.yourapp`) to **both** the app target and the
  extension target, and pass it as `extensionGroupID` when you initialize.
</Step>
<Step title="Subclass the base class">
  Link **`CometChatPushNotificationsSwift` and `CometChatPushNotificationsChat` only** to the
  extension target, and replace the generated class:

```swift
import CometChatPushNotificationsChat

class NotificationService: CometChatNotificationServiceExtension {}
```
</Step>
<Step title="Point the extension at the App Group">
  Add a String entry `CometChatExtensionGroupID` set to your App Group ID in the **extension's**
  `Info.plist`, or override the `extensionGroupID` property instead.
</Step>
</Steps>

Optional overrides: `stripsMarkdown`, `attachesMedia`, and `finalizeContent(_:)` for last-chance
content customization.

<Warning>
  Never link `CometChatPushNotificationsCalls` to the extension. Extensions have a memory limit
  that the Calls SDK does not fit in.
</Warning>

## Configuration reference

Build the configuration with the Swift initializer, or with the builder (also usable from
Objective-C):

<Tabs>
<Tab title="Initializer">
```swift
PNConfiguration(
    appId: String,                            // required
    region: String,                           // required
    providerId: String? = nil,                // required to register tokens — from the dashboard
    enableBadgeCount: Bool = true,            // update the app badge from the payload
    showInAppNotifications: Bool = true,      // foreground banners
    extensionGroupID: String? = nil,          // must match the Notification Service Extension
    authToken: String? = nil,                 // register under your own auth token
    autoRegisterTokens: Bool = true,          // register on login, unregister on logout
    requestNotificationPermission: Bool = true,   // false = ask for permission yourself
    clientHost: String? = nil,                // same value as the Chat SDK's client-host override
    notificationContentModifier: ((UNMutableNotificationContent, CometChatNotificationInfo) -> UNMutableNotificationContent)? = nil
)
```
</Tab>
<Tab title="Builder">
```swift
import CometChatPushNotificationsChat

// Reuses the region from the Chat SDK's AppSettings.
let config = PNConfigurationBuilder.from(appId: "YOUR_APP_ID", settings: appSettings)
    .providerId("YOUR_PROVIDER_ID")
    .extensionGroupID("group.com.yourcompany.yourapp")
    .build()
```

Start from `PNConfiguration.builder(appId:region:)` instead if you don't have the Chat SDK's
`AppSettings` at hand.
</Tab>
</Tabs>

The configuration also has call options: `callKit`, `pushKitOwnership`, `defaultRingTimeoutMs`
and `requestCallPermissions`. They only apply when the Calls product is linked. See
[VoIP Calling](/calls/ios/voip-calling).

## FCM instead of APNs

Set up Firebase as usual and forward the FCM token. The package does not link Firebase.

```swift
func messaging(_ messaging: Messaging, didReceiveRegistrationToken fcmToken: String?) {
    if let token = fcmToken {
        CometChatPushNotifications.shared.registerFCMToken(token)
    }
}
```

APNs is the recommended mode on iOS. For a full FCM walkthrough, see
[iOS FCM Push Notifications](/notifications/ios-fcm-push-notifications).

## Other APIs

| API | Use |
|---|---|
| `setActiveConversation(userId:)` / `setActiveConversation(groupId:)` | Suppress notifications for the chat the user is already looking at |
| `clearActiveConversation()` | Call when that screen closes |
| `clearBadgeCount()` | Reset the app badge |
| `registerTokens(completion:)` / `unregisterTokens(completion:)` | Register or unregister by hand, for example with `autoRegisterTokens: false` |
| `CometChatPushNotifications.parseNotificationInfo(from:)` | Read sender, receiver and body out of a raw payload |
| `CometChatPushNotifications.isCampaignNotification(userInfo:)` | Distinguish campaign pushes from chat pushes |
| `getDiagnostics()` | A dictionary of the SDK's current state, for support tickets |

## Upgrading from 1.0

2.0 removes the 1.0 API with no compatibility layer. For the chat side:

| 1.0 | 2.0 |
|---|---|
| `pod 'CometChatPushNotifications'` / one SPM library | `CometChatPushNotificationsSwift` + `CometChatPushNotificationsChat` |
| `CometChatPushNotificationsConfig(providerId:…)`, initialized after `CometChat.init` | `PNConfiguration(appId:region:providerId:…)`, initialized in `didFinishLaunching` |
| `navigateToChat(for:)` on `CometChatPushNotificationsDelegate` | `navigateToChat(for:)` on `CometChatPushNotificationsChatDelegate` |
| Swift delegate protocol with default implementations | `@objc` protocol with optional methods — the delegate must inherit from `NSObject` |
| `onPushTokenRegistrationFailed(platform:error: CometChatException)` | `error: PNError` |
| `registerDeviceToken(_:onSuccess:onError:)` | `registerDeviceToken(_:completion:)` with `PNResult<String>` |
| NSE `import CometChatPushNotificationsSwift` | `import CometChatPushNotificationsChat` |

Unchanged: `setActiveConversation`, `clearActiveConversation`, `clearBadgeCount`,
`handleBackgroundNotification`, `parseNotificationInfo`, `isCampaignNotification`, and the config
options `enableBadgeCount`, `showInAppNotifications`, `extensionGroupID` and
`notificationContentModifier`.

All call APIs (`presentCallScreen`, `notifyCallsSDKReady`, `foregroundCallPresentation`,
`CometChatIncomingCallView`, …) moved to the Calls product with a new design. See the
[ringing migration guide](/calls/ios/ringing-migration).

## Testing checklist

- Confirm the provider exists in the dashboard and that `providerId` matches it.
- Watch `onPushTokenRegistrationFailed`. A wrong Provider ID shows up there first.
- Send a message to the logged-in user with the app in the foreground, in the background, and
  terminated. Tap each notification and check that it opens the right chat.
- Log out, send another message, and check that **no** notification arrives.
