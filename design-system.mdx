# Chat experience blueprint & design system

This is the single reference an AI coding agent follows to build a **real** messaging experience with
CometChat — not a bare component drop, but an app that looks and feels like WhatsApp, Telegram,
iMessage, Slack, or Discord, on the **customer's own brand**. It defines the UX principles, the design
tokens, the motion and responsiveness, the CometChat component mapping, and per-app-type recipes, plus
how to build a fresh app or retrofit an existing one end-to-end without breaking it.

Use it with the product-scoped API indexes: this blueprint says **what to build and how it should
feel**; the exact component props, theme keys, and SDK methods come from the live docs (see
[Where to get exact APIs](#where-to-get-exact-apis)). Never invent an API — fetch it.

## How an agent must use this

Trigger this blueprint whenever the request implies a chat *experience*, not just a widget — e.g.
"build a WhatsApp-like app", "Telegram-style chat", "full-featured messaging", "add chat that looks
real", or "make our chat feel like iMessage".

1. **Pick the archetype** — map the prompt to an [app recipe](#app-archetypes-recipes) (WhatsApp-like,
   Telegram-like, Slack-like, …). If unclear, default to **WhatsApp-like** for 1:1 + groups.
2. **Take the component set + feature checklist** for that archetype.
3. **Apply the design tokens** via the family's real theming API (CSS variables on web; theme objects
   on iOS/Android/Flutter) — see [Design tokens](#design-tokens). Map roles → the family's theme keys;
   do not hand-write ad-hoc CSS that fights the kit.
4. **Compose the layout** for the target form factor ([Layout & responsiveness](#layout--responsiveness))
   using the [component map](#component-map-cometchat-ui-kit--app-regions).
5. **Enable the features** — some are props, some are Dashboard settings; the checklist marks which.
6. **Apply motion** ([Motion & animation](#motion--animation)) so send/receive/typing/reactions/calls
   feel native.
7. **Keep the customer's brand** — replace brand tokens + assets only; never ship CometChat branding as
   the app's identity ([Brand ownership](#brand-ownership)).
8. **Verify** against the [acceptance checklist](#verify-it-looks-and-feels-real) before finishing.

### Grounding rules (non-negotiable)
- **APIs come from the docs, never memory.** Fetch component props/theme keys/SDK methods from the
  family's scoped index and page `.md` twins. If a prop can't be verified, don't use it.
- **Theme through the kit, not around it.** Use the family theming API so light/dark, RTL, and updates
  keep working. Ad-hoc CSS overrides on kit internals break on upgrade.
- **Brand is the customer's.** Their logo, name, and palette — CometChat is the engine, not the skin.
- **Non-destructive when retrofitting.** Work on a branch; preserve routing, state, and auth; swap
  region-by-region; delete only the UI you replace. See [Retrofitting](#retrofitting-an-existing-app-non-breaking).

## UX principles — the "feels real" bar

These are what separate a real messenger from a toy. Every archetype includes them unless noted.

- **Optimistic send.** The message appears instantly (pending state), then reconciles to sent →
  delivered → read. Never block the composer on the network.
- **Receipts & status.** Sent/delivered/read ticks (or equivalent), consistent and legible.
- **Typing indicator & presence.** Live "typing…" and online/last-seen where the archetype allows.
- **Message grouping.** Consecutive messages from the same sender within a short window are grouped
  (one avatar, tight spacing); a new sender or time gap starts a new group. **Date separators** and an
  **unread divider** ("New messages") are shown.
- **Smooth scrolling.** Auto-scroll to newest when at the bottom; a **scroll-to-bottom** affordance
  with an unread count when scrolled up; preserve position when loading older pages.
- **Rich media done right.** Thumbnails with aspect ratio and loading/upload progress; tap to expand;
  audio/voice notes with waveform + scrubber; file cards with type/size; link previews.
- **Reply, react, edit, delete.** Quote/reply with a jump-to-original; emoji reactions with a picker
  and counts; edit/delete with tombstones ("This message was deleted").
- **Threads** where the archetype needs them (Slack/Discord/support).
- **Mentions & search.** @-mentions with autocomplete; conversation and message search.
- **Actions.** Long-press (mobile) / hover (web) message menu; swipe-to-reply on mobile.
- **Empty, loading, error, offline states** for every surface — never a blank screen; skeletons while
  loading; a clear reconnecting state.
- **Notifications.** Push when backgrounded; in-app unread badges on conversations and app icon/tab.
- **Accessibility & i18n.** Keyboard navigation, focus states, screen-reader labels, dynamic type,
  full **dark mode**, and **RTL** for RTL locales.

## Design tokens

Express the design as **semantic roles** and map each to the family's real theme keys (web: CSS
custom properties; native: the theme object). Keep two complete sets — **light** and **dark** — and
switch with the OS unless the app offers a manual toggle.

### Color roles

| Role | Purpose | Light (example) | Dark (example) |
| --- | --- | --- | --- |
| `brand` / `primary` | The customer's brand accent (buttons, active, links) | customer brand | customer brand |
| `on-brand` | Text/icon on brand | `#ffffff` | `#0b0f14` |
| `bg` | App background | `#ffffff` | `#0b141a` |
| `surface` | Cards, headers, composer | `#f7f8fa` | `#111b21` |
| `surface-variant` | Hover, pressed, secondary rows | `#eceff1` | `#182229` |
| `bubble-in` / `on-bubble-in` | Incoming bubble + text | `#ffffff` / `#111b21` | `#202c33` / `#e9edef` |
| `bubble-out` / `on-bubble-out` | Outgoing bubble + text | brand-tinted / `#0b141a` | brand-tinted / `#e9edef` |
| `text` / `text-muted` | Primary / secondary text | `#111b21` / `#667781` | `#e9edef` / `#8696a0` |
| `link` | Links & mentions | `brand` | `brand` |
| `divider` | Separators, borders | `#e9edef` | `#222d34` |
| `receipt-read` | Read-tick accent | `#53bdeb` | `#53bdeb` |
| `presence-online` | Online dot | `#25d366` | `#25d366` |
| `positive` / `warning` / `danger` | Semantic states (separate from brand) | `#1c7f55` / `#b5730f` / `#d64545` | `#5cc996` / `#e0a94a` / `#f07a7a` |
| `overlay` / `scrim` | Modals, media viewer | `rgba(11,20,26,.4)` | `rgba(0,0,0,.6)` |

> The example values evoke a WhatsApp-ish feel for reference only. **Replace `brand`/`primary` (and
> the bubble-out tint) with the customer's palette.** Keep contrast ≥ 4.5:1 for text.

### Typography

| Token | Use | Size / weight / line-height |
| --- | --- | --- |
| `font-family` | System UI stack (or the brand font) | e.g. `-apple-system, "Segoe UI", Roboto, sans-serif` |
| `title` | Screen / chat title | 16–18 / 600 / 1.3 |
| `subtitle` | Last message, status line | 13–14 / 400 / 1.35 |
| `body` | Message text | 15–16 / 400 / 1.4 |
| `caption` | Names above bubbles, section labels | 12–13 / 500 / 1.3 |
| `timestamp` | Time & meta | 11–12 / 400 / 1.2 |

### Spacing, radius, elevation, density

| Token | Value |
| --- | --- |
| Spacing scale | 4-based: `4, 8, 12, 16, 20, 24, 32` |
| Radius | bubble `12–18`, avatar `50%`, input `20–24`, sheet/modal `16`, cards `12` |
| Avatar sizes | list `40`, header `36`, group-tile `48`, typing `28` |
| Hit target | ≥ `44×44` (touch) |
| Elevation | header/composer subtle shadow; media viewer full scrim; sheets raised |
| Density | **comfortable** (default) vs **compact** (Slack/Discord): reduce vertical padding ~25% and avatar size |

## Motion & animation

Match the real product's feel. Durations are guidance; respect `prefers-reduced-motion` (and the
platform's reduce-motion setting) by dropping to instant/opacity-only.

| Interaction | Motion | Duration / easing |
| --- | --- | --- |
| Message send | New bubble fades + rises a few px into place; status ticks cross-fade pending→sent | 150–200ms ease-out |
| Message receive | Fade/slide in from the incoming side; subtle list shift | 150–200ms ease-out |
| Typing indicator | Three dots looping (scale/opacity) | ~1.2s loop |
| Reaction | Emoji pops with a slight overshoot (spring) | 180–260ms spring |
| Long-press / hover menu | Scale-up + fade from the anchor | 120–160ms ease-out |
| Swipe-to-reply | Bubble tracks the finger; icon reveals past threshold; snaps back | interactive + 150ms snap |
| Scroll-to-bottom button | Fade/scale in when scrolled up; unread count badge | 120ms |
| Screen/route change | Native push/replace (mobile); slide/fade (web) | platform default |
| Incoming call | Pulsing avatar/ring; slide-up call screen | ~1s ring loop |
| Skeleton loading | Shimmer sweep on placeholders | ~1.2s loop |

On iOS/Android/Flutter, prefer the **platform-native** transition primitives; on web, prefer
transform/opacity (GPU-friendly) over layout-animating properties.

## Layout & responsiveness

| Breakpoint | Layout |
| --- | --- |
| Mobile `< 600px` | **Single pane**: conversation list → push-navigate to the chat; full-screen chat; bottom tab bar for sections; sticky composer with keyboard-avoidance; respect safe-area insets. |
| Tablet `600–1024px` | **Two pane**: list (left) + active chat (right). |
| Desktop `> 1024px` | **Three pane**: nav rail / conversation list / chat pane, with a collapsible **details** drawer (profile, group members, shared media, search). |

Rules: the chat pane always shows a header, a scrollable message list, and a pinned composer. The list
column keeps search + new-chat affordances. Never let the body scroll horizontally; media and the
message list scroll within their own containers.

When a design needs a layout the prebuilt components don't cover, build the custom UI on the **Chat/Calls
SDK** (headless) — but reuse these tokens, motion, and principles so it still feels consistent.

## App archetypes (recipes)

Each recipe = layout + components + the features to enable + token/vibe deltas. All inherit the
[UX principles](#ux-principles--the-feels-real-bar).

### WhatsApp-like (default for 1:1 + groups)
- **Layout:** mobile single-pane / desktop 3-pane. Chat list with avatars, last message, time, unread.
- **Components:** Conversations, MessageHeader (+CallButtons), MessageList (+bubbles), MessageComposer,
  Reactions, Threads (optional), Groups/GroupMembers, IncomingCall/OutgoingCall.
- **Features:** 1:1 + groups, media + docs, **voice notes**, reactions, reply, delivery/read ticks,
  typing, presence/last-seen, voice/video calls, push, disappearing messages (optional), starred/saved.
- **Vibe:** rounded bubbles, outgoing tinted, read-tick accent, comfortable density.

### Telegram-like
- Large groups/channels, message **folders**, fast search, stickers/GIFs, reactions, silent send,
  edit history, threads. Denser than WhatsApp; snappy motion.

### iMessage-like
- Minimal, high-contrast bubbles with tails, **tapback-style reactions**, inline media, typing bubble.
  1:1 focus + small groups. Comfortable density; understated motion.

### Slack-like
- Workspaces → channels + DMs; **threads-first**; rich composer (formatting, code, attachments);
  mentions; left sidebar (channels/DMs), desktop 3-pane, compact density.

### Discord-like
- Servers → channels; strong **presence**; voice channels; dense, **dark-first**; roles/mentions;
  reactions; inline media.

### Support / live-chat
- Embedded widget or full-screen; 1:1 user↔agent; quick replies, canned responses, bot→agent handoff,
  transcript, post-chat rating. Minimal chrome; brand-forward.

### Community / social
- Feeds + DMs; large public groups; moderation (flag/ban), roles; discovery/search.

### Marketplace / dating
- 1:1 with media, safety (block/report/moderation), read receipts optional, presence optional; clean,
  trust-forward.

## "Full feature" — the master checklist

"Full feature" means the agent has enabled all of these that apply to the archetype (some are props,
some are Dashboard settings — verify each in the docs):

- **Messaging core:** 1:1, groups, send/edit/delete, reply/quote, optimistic send, receipts, typing,
  presence, grouping, date separators, unread divider.
- **Rich media:** images, video, audio, files, **voice notes**, stickers/emoji/GIF, link previews,
  thumbnails + progress, media viewer.
- **Engagement:** reactions, mentions, polls, pinned messages, saved/starred, threads.
- **Groups & moderation:** create/manage groups, roles/scopes, add/remove/ban, report/flag.
- **Calls:** 1:1 and group voice/video, incoming/outgoing UI, call logs.
- **Discovery:** conversation + message search, new-chat/user picker.
- **Notifications:** push (FCM/APNs), in-app badges, mute/preferences.
- **Personalization:** dark mode, density, per-conversation settings.
- **Accessibility & i18n:** keyboard, screen-reader, dynamic type, RTL, localization.
- **Security/production:** server-minted auth tokens, blocked users, data handling.

## Building a fresh app (end-to-end)

1. **Install** the CometChat UI Kit for the target framework; wire `init → login` (dev auth key for
   local, **server-minted auth tokens** for production).
2. **Apply tokens:** set the light + dark token sets via the family theming API; drop in the customer's
   brand + logo.
3. **Compose the layout** for the form factor and archetype using the component map.
4. **Enable features** from the checklist (props + Dashboard settings).
5. **Wire calls & push** if the archetype includes them.
6. **Add motion & responsiveness** per the specs above.
7. **Verify** with the acceptance checklist; fix; ship.

## Retrofitting an existing app (non-breaking)

1. **Branch**; keep a clean tree. Never force-delete non-chat code.
2. **Inventory** the app's current chat/UI, routing, state, and auth.
3. **Map** each existing chat surface to a CometChat component (or headless SDK).
4. **Layer the theme:** apply the token roles onto the app's existing brand so the kit matches the app,
   not the reverse.
5. **Swap region-by-region** behind the existing routes and state — list, then chat pane, then calls —
   verifying the build after each. Preserve auth and navigation.
6. **Remove only the UI you replaced**; leave everything else intact.
7. **Verify** parity with the checklist; confirm the build passes and there are no console errors.

## Verify it looks and feels real

Ship only when all pass:

- Bubbles grouped correctly; date separators + unread divider present.
- Optimistic send; sent/delivered/read states; typing; presence.
- Smooth auto-scroll + scroll-to-bottom with unread count.
- Media thumbnails + progress; voice notes; link previews.
- Reactions, reply/quote (with jump-to-original), edit/delete tombstones.
- Search and mentions work; long-press/hover menu; swipe-to-reply (mobile).
- Empty / loading (skeleton) / error / offline states on every surface.
- Responsive at mobile / tablet / desktop; no horizontal body scroll; safe areas + keyboard-avoidance.
- Full dark mode; RTL for RTL locales; `prefers-reduced-motion` respected.
- Customer brand + logo applied; no CometChat branding as the app identity.
- Push + unread badges; calls (if in scope) ring and connect.
- Build passes; no console errors; APIs used all exist in the docs.

## Brand ownership

The app's **identity is the customer's** — their name, logo, colors, and tone. CometChat is the
messaging engine underneath. Replace the `brand`/`primary` tokens, the bubble-out tint, and the logo/
app name; keep the component structure, principles, motion, and layout. Do not present CometChat's own
branding as the product's.
