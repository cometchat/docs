Token Based File Access lets you control how media files (images, videos, audio, documents) are accessed on CometChat's secure media servers. The SDK supports two modes — **Legacy** (FAT appended as a query parameter automatically) and **Header-Based** (clean URLs with FAT sent via HTTP headers). Once Token Based File Access is enabled in the CometChat Dashboard, it cannot be disabled.

<Note>
**Available via:** SDK | [REST API](https://api-explorer.cometchat.com) | [CometChat Dashboard](https://app.cometchat.com)
</Note>

<Warning>
Enabling Token Based File Access is **irreversible**. Once you enable this feature in the CometChat Dashboard, it cannot be disabled. All media URLs will require a valid File Access Token (FAT) for access. Make sure your application is ready to handle secure media URLs before enabling.
</Warning>

## Prerequisites

Before using Token Based File Access in your application, ensure the following:

1. **Enable in Dashboard:** Navigate to your CometChat Dashboard → **Chats** → **Settings** and enable the **Token Based File Access** configuration. This is a one-time setup step that activates token-based media access for your app.

2. **SDK Initialization:** Your application must initialize the CometChat SDK with a valid App ID and region before configuring secure media modes. See [Setup SDK](/sdk/android/overview) for details.

<Warning>
Once Token Based File Access is enabled, all media URLs served by CometChat's secure media servers require a valid **File Access Token (FAT)** for access. Any request to a media URL without a valid FAT will receive a **401 Unauthorized** response. Ensure your application handles secure media URLs before enabling this feature.
</Warning>

## Secure Media Modes

CometChat supports two modes for accessing media files on its secure media servers. The mode is configured during SDK initialization using `AppSettingsBuilder.setSecureMediaMode()` or after initialization using `CometChat.setSecureMediaMode()`.

### Legacy Mode (Default)

Legacy Mode (`SecureMediaMode.LEGACY`) is the default mode. In this mode, the SDK automatically appends the File Access Token (FAT) as a `?fat=<token>` query parameter to all media URLs. No additional work is required from the developer — media URLs are ready to use as-is.

- The SDK handles FAT injection transparently
- Media URLs include the token directly: `https://files-<region>.cometchat.io/<app_id>/media/file.jpg?fat=eyJhbGci...`
- Suitable for simple integrations where clean URLs are not a concern
- Works out of the box with ImageView, VideoView, and MediaPlayer

### Header-Based Mode

Header-Based Mode (`SecureMediaMode.HEADER_BASED`) provides clean media URLs without embedded tokens. In this mode, the FAT is sent via HTTP headers instead of URL parameters. Use `CometChat.getSecureMediaClientBuilder()` for image loading with Glide, or `CometChat.getSecureMediaHeaders()` for audio/video playback.

- Media URLs remain clean without query parameters
- FAT is automatically injected as an HTTP header by the secure client
- Use `CometChat.getSecureMediaClientBuilder()` to get a pre-configured OkHttpClient for Glide
- Use `CometChat.getSecureMediaHeaders(url)` to get headers for MediaPlayer/ExoPlayer
- Ideal for applications that need clean URLs or custom media handling logic

### SecureMediaMode Enum

The `SecureMediaMode` enum defines the available secure media access modes:

| Value | Description |
| --- | --- |
| `SecureMediaMode.LEGACY` | Default mode. FAT is appended as a `?fat=<token>` query parameter to media URLs automatically by the SDK. |
| `SecureMediaMode.HEADER_BASED` | Clean URL mode. FAT is sent via HTTP headers. Use `getSecureMediaClientBuilder()` or `getSecureMediaHeaders()` to access media. |

## Configuration

Configure the secure media mode during SDK initialization using `AppSettingsBuilder.setSecureMediaMode()`, or set it after initialization using `CometChat.setSecureMediaMode()`.

<Tabs>
<Tab title="Kotlin">
```kotlin
// Option 1: Configure during SDK initialization
val appSettings = AppSettings.AppSettingsBuilder()
    .subscribePresenceForAllUsers()
    .setRegion("YOUR_REGION")
    .setSecureMediaMode(SecureMediaMode.HEADER_BASED)
    .autoEstablishSocketConnection(true)
    .build()

CometChat.init(this, "YOUR_APP_ID", appSettings, object : CometChat.CallbackListener<String>() {
    override fun onSuccess(successMessage: String?) {
        Log.d(TAG, "Initialization completed with HEADER_BASED mode")
    }

    override fun onError(e: CometChatException?) {
        Log.e(TAG, "Initialization failed: ${e?.message}")
    }
})

// Option 2: Set after initialization
CometChat.setSecureMediaMode(SecureMediaMode.HEADER_BASED)
```
</Tab>


If you omit `setSecureMediaMode()`, the SDK defaults to **Legacy Mode** (`SecureMediaMode.LEGACY`). In Legacy Mode, the SDK automatically appends the FAT as a query parameter to media URLs — no additional configuration is needed.
</Note>

## Loading Images with Glide

When using **Header-Based Mode**, use `CometChat.getSecureMediaClientBuilder()` to get a pre-configured OkHttpClient.Builder that automatically injects FAT headers. Register this client with Glide to load secure images.

<Tabs>
<Tab title="Kotlin">
```kotlin
// Create a custom Glide module to use the secure client
@GlideModule
class SecureGlideModule : AppGlideModule() {
    override fun registerComponents(context: Context, glide: Glide, registry: Registry) {
        // Get the secure client builder from CometChat
        val client = CometChat.getSecureMediaClientBuilder()
            .connectTimeout(30, TimeUnit.SECONDS)
            .readTimeout(30, TimeUnit.SECONDS)
            .build()

        // Register with Glide
        registry.replace(
            GlideUrl::class.java,
            InputStream::class.java,
            OkHttpUrlLoader.Factory(client)
        )
    }
}

// Then use Glide normally - FAT headers are injected automatically
Glide.with(context)
    .load(imageUrl)
    .into(imageView)
```
</Tab>
<Tab title="Java">
```java
// Create a custom Glide module to use the secure client
@GlideModule
public class SecureGlideModule extends AppGlideModule {
```

## Playing Audio with MediaPlayer

For audio playback, use `CometChat.getSecureMediaHeaders()` to get the headers map and pass it to MediaPlayer.

<Tabs>
<Tab title="Kotlin">
```kotlin
fun playAudio(audioUrl: String) {
    val mediaPlayer = MediaPlayer()

    try {
        // Get secure headers for the audio URL
        val headers = CometChat.getSecureMediaHeaders(audioUrl)

        // Set data source with headers
        mediaPlayer.setDataSource(context, Uri.parse(audioUrl), headers)
        mediaPlayer.prepareAsync()

        mediaPlayer.setOnPreparedListener { mp ->
            mp.start()
        }
    } catch (e: IOException) {
        Log.e(TAG, "Error playing audio: ${e.message}")
    }
}
```
</Tab>

## Playing Video with ExoPlayer

For video playback with ExoPlayer, use `CometChat.getSecureMediaHeaders()` to configure the data source factory.

<Tabs>
<Tab title="Kotlin">
```kotlin
fun playVideo(videoUrl: String) {
    // Get secure headers
    val headers = CometChat.getSecureMediaHeaders(videoUrl)

    // Create data source factory with headers
    val dataSourceFactory = DefaultHttpDataSource.Factory()
        .setDefaultRequestProperties(headers)

    // Create media source
    val mediaItem = MediaItem.fromUri(videoUrl)
    val mediaSource = ProgressiveMediaSource.Factory(dataSourceFactory)
        .createMediaSource(mediaItem)

    // Play
    val player = ExoPlayer.Builder(context).build()
    player.setMediaSource(mediaSource)
    player.prepare()
    player.play()
}
```

## Downloading Files

Use `CometChat.getSecureMediaClientBuilder()` to download files securely.

<Tabs>
<Tab title="Kotlin">
```kotlin
fun downloadFile(fileUrl: String, destination: File) {
    // Get secure client
    val client = CometChat.getSecureMediaClientBuilder().build()

    val request = Request.Builder()
        .url(fileUrl)
        .build()

    client.newCall(request).enqueue(object : Callback {
        override fun onResponse(call: Call, response: Response) {
            if (response.isSuccessful) {
                response.body?.byteStream()?.use { inputStream ->
                    FileOutputStream(destination).use { outputStream ->
                        inputStream.copyTo(outputStream)
                    }
                }
                Log.d(TAG, "File downloaded successfully")
            }
        }

        override fun onFailure(call: Call, e: IOException) {
            Log.e(TAG, "Download failed: ${e.message}")
        }
    })
}
```
</Tab>
<Tab title="Java">
```java
public void downloadFile(String fileUrl, File destination) {
    // Get secure client
    OkHttpClient client = CometChat.getSecureMediaClientBuilder().build();

    Request request = new Request.Builder()
        .url(fileUrl)
        .build();

    client.newCall(request).enqueue(new Callback() {
        @Override
        public void onResponse(Call call, Response response) throws IOException {
            if (response.isSuccessful()) {
                try (InputStream is = response.body().byteStream();
                     FileOutputStream fos = new FileOutputStream(destination)) {
                    byte[] buffer = new byte[4096];
                    int read;
                    while ((read = is.read(buffer)) != -1) {
                        fos.write(buffer, 0, read);
                    }
                }
                Log.d(TAG, "File downloaded successfully");
            }
        }

        @Override
        public void onFailure(Call call, IOException e) {
            Log.e(TAG, "Download failed: " + e.getMessage());
        }
    });
}
```
</Tab>
</Tabs>

## How Attachment URLs Differ

When Token Based File Access is enabled, the format of media attachment URLs depends on the configured mode.

### Legacy Mode

In Legacy Mode, the SDK automatically appends the File Access Token (FAT) as a `?fat=<token>` query parameter to every media URL. Attachment URLs returned by the SDK are ready to use directly.

```
https://files-<region>.cometchat.io/<app_id>/media/file.jpg?fat=eyJhbGciOiJIUzI1NiIs...
```

- URLs are self-contained and can be used directly with Glide, Coil, Picasso, or ImageView
- No developer action is required at render time

### Header-Based Mode

In Header-Based Mode, attachment URLs remain clean without any token parameters. Use `CometChat.getSecureMediaClientBuilder()` or `CometChat.getSecureMediaHeaders()` to access media with FAT headers.

```
https://files-<region>.cometchat.io/<app_id>/media/file.jpg
```

- URLs do not contain any token information
- Use `getSecureMediaClientBuilder()` for Glide/image loading
- Use `getSecureMediaHeaders(url)` for MediaPlayer/ExoPlayer

## API Reference

The following methods are available on the `CometChat` class for working with Token Based File Access:

| Method | Return Type | Description |
| --- | --- | --- |
| `setSecureMediaMode(mode)` | `void` | Sets the secure media mode. Pass `SecureMediaMode.LEGACY` or `SecureMediaMode.HEADER_BASED`. |
| `getSecureMediaMode()` | `SecureMediaMode` | Returns the current secure media mode. |
| `getSecureMediaClientBuilder()` | `OkHttpClient.Builder` | Returns a pre-configured OkHttpClient.Builder with automatic FAT header injection. Use for Glide setup and file downloads. |
| `getSecureMediaHeaders(url)` | `Map<String, String>` | Returns a map of HTTP headers needed for secure media access. Use for MediaPlayer and ExoPlayer. |
| `requiresSecureMediaAccess(url)` | `boolean` | Returns `true` if the URL points to CometChat's secure media servers and requires FAT authentication. |

## Error Handling

When working with Token Based File Access, handle these common error scenarios gracefully.

### 401 Unauthorized

A 401 response means the FAT is missing, expired, or invalid. The SDK automatically refreshes the FAT on re-login.

<Tabs>
<Tab title="Kotlin">
```kotlin
// Handle 401 by re-authenticating
fun handleMediaError(responseCode: Int) {
    if (responseCode == 401) {
        Log.e(TAG, "FAT expired or invalid - user needs to re-login")
        // Prompt user to re-authenticate
        // The SDK refreshes FAT automatically on login
    }
}
```

## Best Practices

<AccordionGroup>
  <Accordion title="Configure Glide Once">
    Set up your Glide module with `CometChat.getSecureMediaClientBuilder()` once during app initialization. This ensures all image loading automatically includes FAT headers without any additional code at each load site.
  </Accordion>

  <Accordion title="Use the Right Method for Each Media Type">
    - **Images**: Use `getSecureMediaClientBuilder()` with Glide
    - **Audio/Video**: Use `getSecureMediaHeaders()` with MediaPlayer or ExoPlayer
    - **File Downloads**: Use `getSecureMediaClientBuilder()` with OkHttp
  </Accordion>

  <Accordion title="Check URL Before Loading">
    Use `CometChat.requiresSecureMediaAccess(url)` to check if a URL needs secure access. This is useful when loading mixed content (CometChat media + external URLs).

    ```kotlin
    if (CometChat.requiresSecureMediaAccess(url)) {
        // Use secure client
        loadWithSecureClient(url)
    } else {
        // Regular URL - load normally
        loadNormally(url)
    }
    ```
  </Accordion>

  <Accordion title="Handle 401 Gracefully">
    A 401 response means the FAT has expired. The SDK refreshes the FAT automatically on login. Implement retry logic or prompt the user to re-authenticate when you encounter 401 errors on media requests.
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="401 Unauthorized on Media URLs">
    **Symptom:** Media files fail to load with 401 Unauthorized.

    **Possible causes:**
    - FAT has expired or is missing
    - In Header-Based Mode, not using `getSecureMediaClientBuilder()` or `getSecureMediaHeaders()`
    - SDK not initialized properly

    **Solution:**
    1. Verify SDK is initialized and user is logged in
    2. In Header-Based Mode, use `CometChat.getSecureMediaClientBuilder()` for images or `CometChat.getSecureMediaHeaders()` for audio/video
    3. If FAT expired, re-authenticate the user
  </Accordion>

  <Accordion title="Images Not Loading with Glide">
    **Symptom:** Images fail to load in Header-Based Mode.

    **Solution:** Ensure you've configured Glide with the secure client:

    ```kotlin
    @GlideModule
    class SecureGlideModule : AppGlideModule() {
        override fun registerComponents(context: Context, glide: Glide, registry: Registry) {
            val client = CometChat.getSecureMediaClientBuilder().build()
            registry.replace(GlideUrl::class.java, InputStream::class.java,
                OkHttpUrlLoader.Factory(client))
        }
    }
    ```
  </Accordion>

  <Accordion title="Audio/Video Won't Play">
    **Symptom:** MediaPlayer or ExoPlayer fails to play media.

    **Solution:** Use `getSecureMediaHeaders()` to get the headers map:

    ```kotlin
    // ❌ Wrong - no headers
    mediaPlayer.setDataSource(audioUrl)

    // ✅ Correct - with headers
    val headers = CometChat.getSecureMediaHeaders(audioUrl)
    mediaPlayer.setDataSource(context, Uri.parse(audioUrl), headers)
    ```
  </Accordion>

  <Accordion title="Debug Current Configuration">
    Use this code to debug your secure media configuration:

    ```kotlin
    Log.d(TAG, "Mode: ${CometChat.getSecureMediaMode()}")
    Log.d(TAG, "Requires auth: ${CometChat.requiresSecureMediaAccess(mediaUrl)}")
    Log.d(TAG, "Headers: ${CometChat.getSecureMediaHeaders(mediaUrl)}")
    ```
  </Accordion>
</AccordionGroup>
