{/* TL;DR for Agents and Quick Reference */}
<Accordion title="AI Integration Quick Reference">

```kotlin
// 1. Build an OfflineConfig (off by default — call enabled(true)).
val offlineConfig = OfflineConfig.Builder()
    .enabled(true)
    .build()

// 2. Attach it to AppSettings.
val appSettings = AppSettings.AppSettingsBuilder()
    .setRegion("REGION")
    .setOfflineConfig(offlineConfig)   // explicit config; enabled value wins
    // .offline(true)                  // shorthand: enable with all defaults
    .build()

// 3. Pass the settings to init.
CometChat.init(context, "APP_ID", appSettings, callbackListener)

// 4. Verify it is active for the logged-in user.
val active = CometChat.isOfflineEnabled()   // Boolean
```

</Accordion>

Offline support is **off by default**. You turn it on once, at initialization, by attaching an `OfflineConfig` to your `AppSettings`. Until you do, the SDK behaves exactly as before. This page covers the minimal setup; for every tunable option see the [Configuration & API Reference](/sdk/android/v5/offline-reference).

<Steps>

<Step title="Requirements">
Offline support requires CometChat Android SDK **5.1.0** or later (minSdk 21). Add or update the dependency:

<Tabs>
<Tab title="Java">
```groovy
implementation "com.cometchat:chat-sdk-android:5.1.0"
```
</Tab>
<Tab title="Kotlin">
```kotlin
implementation("com.cometchat:chat-sdk-android:5.1.0")
```
</Tab>
</Tabs>

If you are new to the SDK, complete the [standard setup](/sdk/android/v5/setup) first; the steps below only add offline configuration to your existing `init`.
</Step>

<Step title="Build an OfflineConfig">
Construct an `OfflineConfig` with its fluent `Builder` and call `enabled(true)`. Every other field has a sensible default, so set only what you need.

<Tabs>
<Tab title="Java">
```java
OfflineConfig offlineConfig = new OfflineConfig.Builder()
        .enabled(true)
        .build();
```
</Tab>
<Tab title="Kotlin">
```kotlin
val offlineConfig = OfflineConfig.Builder()
    .enabled(true)
    .build()
```
</Tab>
</Tabs>
</Step>

<Step title="Attach it to AppSettings">
Pass the config to `AppSettingsBuilder.setOfflineConfig(...)`. To enable with all defaults instead of building a config, use the `offline(boolean)` shorthand.

<Tabs>
<Tab title="Java">
```java
AppSettings appSettings = new AppSettings.AppSettingsBuilder()
        .setRegion("REGION")
        .setOfflineConfig(offlineConfig)   // explicit config
        // .offline(true)                  // shorthand: enable with defaults
        .build();
```
</Tab>
<Tab title="Kotlin">
```kotlin
val appSettings = AppSettings.AppSettingsBuilder()
    .setRegion("REGION")
    .setOfflineConfig(offlineConfig)       // explicit config
    // .offline(true)                      // shorthand: enable with defaults
    .build()
```
</Tab>
</Tabs>

<Note>
If you call both `setOfflineConfig(...)` and `offline(boolean)`, the explicit `OfflineConfig` wins — its `enabled` value is authoritative.
</Note>
</Step>

<Step title="Initialize the SDK">
Pass the settings to `CometChat.init(...)` as you do today. No other call changes.

<Tabs>
<Tab title="Java">
```java
CometChat.init(context, "APP_ID", appSettings, new CometChat.CallbackListener<String>() {
    @Override
    public void onSuccess(String successMessage) {
        Log.d(TAG, "Initialization completed successfully");
    }

    @Override
    public void onError(CometChatException e) {
        Log.e(TAG, "Initialization failed: " + e.getMessage());
    }
});
```
</Tab>
<Tab title="Kotlin">
```kotlin
CometChat.init(context, "APP_ID", appSettings, object : CometChat.CallbackListener<String>() {
    override fun onSuccess(successMessage: String?) {
        Log.d(TAG, "Initialization completed successfully")
    }

    override fun onError(e: CometChatException?) {
        Log.e(TAG, "Initialization failed: ${e?.message}")
    }
})
```
</Tab>
</Tabs>
</Step>

<Step title="Verify it is active">
Call `CometChat.isOfflineEnabled()`. It returns `true` only while offline support is actually active for the logged-in user — so it is `false` before anyone logs in, even when you enabled it in `AppSettings`. Read it at the moment of each decision and keep no copy of the result.

<Tabs>
<Tab title="Java">
```java
boolean active = CometChat.isOfflineEnabled();
Log.d(TAG, "Offline support active: " + active);
```
</Tab>
<Tab title="Kotlin">
```kotlin
val active = CometChat.isOfflineEnabled()
Log.d(TAG, "Offline support active: $active")
```
</Tab>
</Tabs>
</Step>

</Steps>

## Enable from a settings file

If you initialize with `CometChat.initFromSettings(...)`, which reads `cometchat-settings.json` from your app's `assets/`, add an `offline` key under `chatSDK`. It accepts a boolean shorthand or a full configuration object.

```json cometchat-settings.json
{
  "appId": "APP_ID",
  "region": "REGION",
  "chatSDK": {
    "offline": true
  }
}
```

<Tabs>
<Tab title="Java">
```java
CometChat.initFromSettings(context, new CometChat.CallbackListener<String>() {
    @Override
    public void onSuccess(String successMessage) {
        Log.d(TAG, "Initialization completed successfully");
    }

    @Override
    public void onError(CometChatException e) {
        Log.e(TAG, "Initialization failed: " + e.getMessage());
    }
});
```
</Tab>
<Tab title="Kotlin">
```kotlin
CometChat.initFromSettings(context, object : CometChat.CallbackListener<String>() {
    override fun onSuccess(successMessage: String?) {
        Log.d(TAG, "Initialization completed successfully")
    }

    override fun onError(e: CometChatException?) {
        Log.e(TAG, "Initialization failed: ${e?.message}")
    }
})
```
</Tab>
</Tabs>
