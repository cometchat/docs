With offline support on, the SDK can cache attachment bytes durably on the device so media stays viewable offline — even after the server's presigned URL has expired. This page covers the caching modes, what downloads automatically, how to read cached bytes, and how to download media on demand.

<Note>

Media caching applies only while offline support is active for the logged-in user (`CometChat.isOfflineEnabled()` is `true`). See [Enable Offline Support](/sdk/android/v5/offline-enable).

</Note>

## Caching modes

The caching mode is set once, in the `OfflineConfig` you pass at initialization, and is fixed for the SDK session. There is no runtime switch — to change it, re-initialize the SDK with a new config.

| `MediaCachingMode` | Behavior |
|---|---|
| `AUTO` (default) | Incoming media bytes are eagerly downloaded and cached on any network, then LRU-managed. The outgoing copy is retained after the server acknowledges the send. |
| `OFF` | Incoming media bytes are **not** cached. The message metadata (including `fileUrl`) is still cached, so the message appears offline and the UI loads media live from the URL when online. The outgoing copy is dropped after the send is acknowledged. |

Sending media always works in both modes.

<Tabs>
<Tab title="Java">
```java
OfflineConfig offlineConfig = new OfflineConfig.Builder()
    .enabled(true)
    .mediaCaching(MediaCachingMode.AUTO)
    .maxMediaCacheSize(500L * 1024 * 1024)
    .build();
```

</Tab>

<Tab title="Kotlin">
```kotlin
val offlineConfig = OfflineConfig.Builder()
    .enabled(true)
    .mediaCaching(MediaCachingMode.AUTO)
    .maxMediaCacheSize(500L * 1024 * 1024)
    .build()
```

</Tab>
</Tabs>

Read the mode in effect at runtime with `CometChat.getMediaCachingMode()`. It returns `MediaCachingMode.OFF` whenever offline support is not active, whatever the app configured, so a UI layer can rely on it without reading the config itself.

## What downloads automatically

In `AUTO` mode, media bytes are downloaded and cached automatically on the two live receive paths:

- a **realtime** media message received while connected, and
- opening a chat **online** (the server read refreshes and caches its media).

A media message that arrives through a reconnect catch-up [sync](/sdk/android/v5/offline-sync) is cached as **metadata only** and renders as a placeholder; its bytes download lazily the next time you open that chat online. This holds in both `AUTO` and `OFF`.

In `OFF` mode, nothing is auto-downloaded on any path; media loads live from its URL when online.

## Reading cached media

When bytes are already cached, the SDK **hydrates the local path automatically** on every message it delivers — you do not have to ask. Read it straight off the attachment:

<Tabs>
<Tab title="Java">
```java
Attachment attachment = mediaMessage.getAttachment();
String localPath = attachment.getLocalPath();   // non-null when bytes are cached
if (localPath != null) {
    // Render directly from disk — no network fetch.
}
```

</Tab>

<Tab title="Kotlin">
```kotlin
val attachment = mediaMessage.attachment
val localPath = attachment.localPath   // non-null when bytes are cached
if (localPath != null) {
    // Render directly from disk — no network fetch.
}
```

</Tab>
</Tabs>

To look up the cached path explicitly, call `getCachedMediaPath`. It is a cheap filesystem check, safe on the main thread, and returns `null` when the bytes are not cached (call `downloadMedia` to fetch them).

<Tabs>
<Tab title="Java">
```java
String path = CometChat.getCachedMediaPath(attachment);  // null if not cached
```

</Tab>

<Tab title="Kotlin">
```kotlin
val path = CometChat.getCachedMediaPath(attachment)      // null if not cached
```

</Tab>
</Tabs>

<Note>

Each attachment of a multi-attachment message resolves independently. An attachment with no cached bytes keeps `localPath == null` and the UI loads it from the URL as before.

</Note>

## Downloading on demand

Call `downloadMedia` to fetch and cache an attachment's bytes — for example when the user taps a placeholder. The SDK runs the resolution off the main thread (cached bytes, then a valid URL, then a re-signed URL if the presigned one expired) and delivers on the main thread.

<Tabs>
<Tab title="Java">
```java
CometChat.downloadMedia(attachment, new MediaCallbackListener() {
    @Override
    public void onSuccess(String localPath) {
        // Bytes cached; render from localPath.
    }

    @Override
    public void onProgress(int percent) {
        // 0..100, best-effort.
    }

    @Override
    public void onError(CometChatException e) { }
});
```

</Tab>

<Tab title="Kotlin">
```kotlin
CometChat.downloadMedia(attachment, object : MediaCallbackListener {
    override fun onSuccess(localPath: String?) {
        // Bytes cached; render from localPath.
    }

    override fun onProgress(percent: Int) {
        // 0..100, best-effort.
    }

    override fun onError(e: CometChatException?) { }
})
```

</Tab>
</Tabs>

`onProgress(int percent)` reports `0..100`, best-effort and monotonic non-decreasing. It is emitted only when the server reports a content length; for an unknown-length download it is skipped and the call goes straight to `onSuccess`. Progress never blocks or fails the download.

## Observe background downloads

In `AUTO` mode, incoming media downloads in the background with no per-call callback. Register a `MediaDownloadListener` to learn when the bytes land (or fail) so a UI tile can refresh. All callbacks fire on the main thread.

<Tabs>
<Tab title="Java">
```java
CometChat.addMediaDownloadListener("MEDIA_LISTENER", new MediaDownloadListener() {
    @Override
    public void onMediaDownloaded(String messageLocalId, String attachmentId, String localPath) {
        // messageLocalId: the message's server id (or local id if not yet sent)
        // attachmentId:   the attachment URL without its query string
        // localPath:      where the bytes landed
    }

    @Override
    public void onMediaDownloadFailed(String messageLocalId, String attachmentId, CometChatException error) { }
});
```

</Tab>

<Tab title="Kotlin">
```kotlin
CometChat.addMediaDownloadListener("MEDIA_LISTENER", object : MediaDownloadListener {
    override fun onMediaDownloaded(messageLocalId: String?, attachmentId: String?, localPath: String?) {
        // messageLocalId: the message's server id (or local id if not yet sent)
        // attachmentId:   the attachment URL without its query string
        // localPath:      where the bytes landed
    }

    override fun onMediaDownloadFailed(messageLocalId: String?, attachmentId: String?, error: CometChatException?) { }
})
```

</Tab>
</Tabs>

Remove the listener with `CometChat.removeMediaDownloadListener("MEDIA_LISTENER")`. The background `MediaDownloadListener` carries no progress callback — progress is reported only on the explicit `downloadMedia` path above.

## Media cache size limit

Cached media bytes are bounded by `maxMediaCacheSize` (default **500 MB**; `0` means unlimited). When the cache exceeds the limit, the least recently accessed media is deleted first until it is back under budget. Media belonging to un-sent messages and in-progress uploads is never evicted and does not count toward the budget.

Media is stored as files in durable, backup-excluded storage; the location is not configurable. Eviction runs silently in the background — there is no cache-limit callback. To reason about size, use `CometChat.getCacheSize()` and the configured limits. See the [configuration reference](/sdk/android/v5/offline-reference) for the full set of options.
