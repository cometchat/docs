With offline support on, the SDK can cache attachment bytes durably on the device so media stays viewable offline — even after the server's signed URL has expired. This page covers the caching modes, how to read cached bytes, and how to download media on demand.

<Note>
Media caching applies only while offline support is active for the logged-in user (`CometChat.isOfflineEnabled()` is `true`). See [Enable Offline Support](/sdk/javascript/offline-enable). In a browser, media bytes are kept in the Origin Private File System (OPFS); **where OPFS is not available, media is not cached** (messages and attachment metadata still are).
</Note>

## Caching modes

The caching mode is set once, in the offline config you pass at initialization, and is fixed for the SDK session. There is no runtime switch — to change it, re-initialize the SDK with a new config.

| `MediaCachingMode` | Behavior |
|---|---|
| `AUTO` (default) | Incoming media bytes are downloaded and cached on receipt, then LRU-managed, so they are available offline. |
| `OFF` | Incoming media bytes are **not** downloaded or cached. The message and its attachment metadata (including the URL) are still cached, so the message appears offline and the UI loads media live from the URL when online. |

Sending media always works in both modes.

Read the mode in effect at runtime with `CometChat.getMediaCachingMode()`. It returns `"OFF"` whenever offline support is not active, whatever the app configured, so a UI layer can rely on it without reading the config itself.

## Reading cached media

When bytes are already cached, the SDK **sets the attachment's local path automatically** on the messages it delivers. Read it with `attachment.getLocalPath()`. In a browser that value is an OPFS storage handle (`opfs:…`), **not** something you can put in an `src` — to render a cached file, ask for an object URL instead.

`getCachedMediaObjectURL` resolves a `blob:` URL for a cached attachment, or `null` when its bytes are not cached. **You must revoke the URL** with `URL.revokeObjectURL` when you are done with it.

<Tabs>
<Tab title="TypeScript">
```typescript
const attachment: CometChat.Attachment = mediaMessage.getAttachment();

const objectUrl: string | null = await CometChat.getCachedMediaObjectURL(attachment);
if (objectUrl) {
  imageElement.src = objectUrl;               // render from disk — no network fetch
  imageElement.onload = () => URL.revokeObjectURL(objectUrl);
} else {
  imageElement.src = attachment.getUrl();     // not cached: load live when online
}
```
</Tab>
<Tab title="JavaScript">
```javascript
const attachment = mediaMessage.getAttachment();

const objectUrl = await CometChat.getCachedMediaObjectURL(attachment);
if (objectUrl) {
  imageElement.src = objectUrl;               // render from disk — no network fetch
  imageElement.onload = () => URL.revokeObjectURL(objectUrl);
} else {

}
```
</Tab>
</Tabs>

To look up the cached handle without creating a URL, call `getCachedMediaPath`. It resolves `null` when the bytes are not cached (call `downloadMedia` to fetch them).

```javascript
const handle = await CometChat.getCachedMediaPath(attachment); // null if not cached
```

<Note>
Each attachment of a multi-attachment message resolves independently. An attachment with no cached bytes has no local path, and the UI loads it from the URL as before.
</Note>

## Downloading on demand

Call `downloadMedia` to fetch and cache an attachment's bytes — for example when the user taps a placeholder. The SDK resolves cached bytes first, then the URL, and re-signs an expired link (HTTP 401, 403 or 410) through the message the attachment was delivered with before retrying once. `downloadMedia` returns nothing; results arrive on the `MediaCallbackListener`.

<Tabs>
<Tab title="TypeScript">
```typescript
CometChat.downloadMedia(
  attachment,
  new CometChat.MediaCallbackListener({
    onSuccess: (localPath: string) => {
      // Bytes cached; render via getCachedMediaObjectURL(attachment).
    },
    onProgress: (percent: number) => {
      // 0..100, best-effort.
    },
    onError: (error: CometChat.CometChatException) => {
      console.log(error.code);
    },
  })
);
```
</Tab>
<Tab title="JavaScript">
```javascript
CometChat.downloadMedia(
  attachment,
  new CometChat.MediaCallbackListener({
    onSuccess: (localPath) => {
      // Bytes cached; render via getCachedMediaObjectURL(attachment).
    },
    onProgress: (percent) => {
      // 0..100, best-effort.
    },
    onError: (error) => {
      console.log(error.code);
    },
  })
);
```
</Tab>
</Tabs>

`downloadMedia` calls `onError` with `ERROR_OFFLINE_DISABLED` when offline support is not running, and with `ERROR_OFFLINE_MEDIA_NO_URL` when no attachment, or an attachment without a URL, is given.

## Observe background downloads

In `AUTO` mode, incoming media downloads in the background with no per-call callback. Register a `MediaDownloadListener` to learn when the bytes land (or fail) so a UI tile can refresh.

<Tabs>
<Tab title="TypeScript">
```typescript
CometChat.addMediaDownloadListener(
  "MEDIA_LISTENER",
  new CometChat.MediaDownloadListener({
    onMediaDownloaded: (messageId: string, attachmentId: string, localPath: string) => {
      // attachmentId: the attachment URL without its query string
    },
    onMediaDownloadFailed: (messageId: string, attachmentId: string, error: CometChat.CometChatException) => {},
  })
);
```
</Tab>
<Tab title="JavaScript">
```javascript
CometChat.addMediaDownloadListener(
  "MEDIA_LISTENER",
  new CometChat.MediaDownloadListener({
    onMediaDownloaded: (messageId, attachmentId, localPath) => {
      // attachmentId: the attachment URL without its query string
    },
    onMediaDownloadFailed: (messageId, attachmentId, error) => {},
  })
);
```
</Tab>
</Tabs>

Remove the listener with `CometChat.removeMediaDownloadListener("MEDIA_LISTENER")`. The background listener carries no progress callback — progress is reported only on the explicit `downloadMedia` path. `MessageListener` also gains optional `onMediaDownloaded` and `onMediaDownloadFailed` callbacks.

## Media cache size limit

Cached media bytes are bounded by `maxMediaCacheSize` (default **500 MB**; `0` means unlimited). When the cache exceeds the limit, the least recently accessed media is deleted first until it is back under budget. Media belonging to un-sent messages and in-progress uploads is never evicted.

Media is stored in OPFS (browser) or as files on disk (Electron); the location is not configurable. Eviction runs silently in the background — there is no cache-limit callback. To reason about size, use `CometChat.getCacheSize()` and the configured limits. See the [reference](/sdk/javascript/offline-reference) for the full set of options.

<Warning>
Cached media files are **not encrypted**, even when you turn on [cache encryption](/sdk/javascript/offline-encryption).
</Warning>
