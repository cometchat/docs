{/* TL;DR for Agents and Quick Reference */}
<Accordion title="AI Integration Quick Reference">

```javascript
// 1. Attach an offline config to AppSettings (off by default — enabled must be true).
const appSetting = new CometChat.AppSettingsBuilder()
  .setRegion("REGION")
  .setOfflineConfig({ enabled: true })   // explicit config; its `enabled` wins
  // .offline(true)                      // shorthand: enable with all defaults
  .build();

// 2. Pass the settings to init.
await CometChat.init("APP_ID", appSetting);

// 3. Verify it is active for the logged-in user.
const active = CometChat.isOfflineEnabled();   // boolean
```

</Accordion>

Offline support is **off by default**. You turn it on once, at initialization, by passing an offline config to the `AppSettingsBuilder`. Until you do, the SDK behaves exactly as before. This page covers the minimal setup; for every tunable option see the [Configuration & API Reference](/sdk/javascript/offline-reference).

<Steps>

<Step title="Requirements">
Offline support requires CometChat JavaScript SDK **4.3.0** or later.

```bash
npm install @cometchat/chat-sdk-javascript@4.3.0
```

If you are new to the SDK, complete the [standard setup](/sdk/javascript/setup-sdk) first; the steps below only add offline configuration to your existing `init`.
</Step>

<Step title="Attach an offline config to AppSettings">
Call `setOfflineConfig(...)` on the `AppSettingsBuilder` with an object whose `enabled` is `true`. Every other key has a sensible default, so set only what you need. To enable with all defaults, use the `offline(true)` shorthand instead.

<Tabs>
<Tab title="TypeScript">
```typescript
const appSetting: CometChat.AppSettings = new CometChat.AppSettingsBuilder()
  .subscribePresenceForAllUsers()
  .setRegion("REGION")
  .autoEstablishSocketConnection(true)
  .setOfflineConfig({ enabled: true })   // explicit config
  // .offline(true)                      // shorthand: enable with defaults
  .build();
```
</Tab>
<Tab title="JavaScript">
```javascript
const appSetting = new CometChat.AppSettingsBuilder()
  .subscribePresenceForAllUsers()
  .setRegion("REGION")
  .autoEstablishSocketConnection(true)
  .setOfflineConfig({ enabled: true })   // explicit config
  // .offline(true)                      // shorthand: enable with defaults
  .build();
```
</Tab>
</Tabs>

<Note>
Offline turns on only for an explicit `enabled: true`. A config object without `enabled` leaves it off. If you call both `setOfflineConfig(...)` and `offline(...)`, the explicit config wins.
</Note>
</Step>

<Step title="Initialize the SDK">
Pass the settings to `CometChat.init(...)` as you do today. No other call changes.

<Tabs>
<Tab title="TypeScript">
```typescript
CometChat.init("APP_ID", appSetting).then(
  (initialized: boolean) => {
    console.log("Initialization completed successfully", initialized);
  },
  (error: CometChat.CometChatException) => {
    console.log("Initialization failed with error:", error);
  }
);
```
</Tab>
<Tab title="JavaScript">
```javascript
CometChat.init("APP_ID", appSetting).then(
  () => {
    console.log("Initialization completed successfully");
  },
  (error) => {
    console.log("Initialization failed with error:", error);
  }
);
```
</Tab>
</Tabs>
</Step>

<Step title="Verify it is active">
Call `CometChat.isOfflineEnabled()`. It returns `true` only while offline support is actually running for the logged-in user — so it is `false` before anyone logs in, after logout, while the server has switched offline off for your app, and while the local store is still opening, even when you enabled it in `AppSettings`. Read it at the moment of each decision and keep no copy of the result.

<Tabs>
<Tab title="TypeScript">
```typescript
const active: boolean = CometChat.isOfflineEnabled();
console.log("Offline support active:", active);
```
</Tab>
<Tab title="JavaScript">
```javascript
const active = CometChat.isOfflineEnabled();
console.log("Offline support active:", active);
```
</Tab>
</Tabs>
</Step>

</Steps>

## Enable from a settings object

If you initialize with `CometChat.initFromSettings(settings)`, add an `offline` key under `chatSDK` in the settings object you pass. It accepts a boolean shorthand or a full configuration object, with the same rules as the code config.

```json settings
{
  "appId": "APP_ID",
  "region": "REGION",
  "chatSDK": {
    "offline": true
  }
}
```

## Supported runtimes

| Runtime | Data store | Media bytes |
|---|---|---|
| Browser | IndexedDB | OPFS. Where OPFS is missing, media is not cached. |
| Electron | SQLite in the main process | Files on disk |

Where IndexedDB is missing or blocked (for example some private-browsing modes), offline stays off for the session and the SDK works online as before.

<Note>
**Electron setup.** Install the optional peer dependencies `electron` (20 or later) and `better-sqlite3-multiple-ciphers` (9 or later), call `registerOfflineIpc()` from `@cometchat/chat-sdk-javascript/electron/main` in the main process, and `installCometChatBridge()` from `@cometchat/chat-sdk-javascript/electron/preload` in your preload script (with `contextIsolation: true`). The main process and the renderer must use the same package version. Browser apps need nothing extra.
</Note>

## Server switch

CometChat can switch offline support off for your app from the server. The server can turn it off, never on: offline runs only when your config enables it **and** the server switch is on. When the switch is off, `isOfflineEnabled()` is `false`.
