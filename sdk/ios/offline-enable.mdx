{/* TL;DR for Agents and Quick Reference */}
<Accordion title="AI Integration Quick Reference">

```swift
// 1. Build an OfflineConfig (off by default — call setEnabled(true)).
let offlineConfig = OfflineConfig.Builder()
    .setEnabled(true)
    .build()
// Swift shorthand: let offlineConfig = OfflineConfig(enabled: true)

// 2. Attach it to AppSettings.
let appSettings = AppSettings.AppSettingsBuilder()
    .setRegion(region: "REGION")
    .setOfflineConfig(offlineConfig)
    .build()

// 3. Pass the settings to init.
CometChat.init(appId: "APP_ID", appSettings: appSettings, onSuccess: { _ in }, onError: { _ in })

// 4. Verify it is active for the logged-in user.
let active = CometChat.isOfflineEnabled()   // Bool
```

</Accordion>

Offline support is **off by default**. You turn it on once, at initialization, by attaching an `OfflineConfig` to your `AppSettings`. Until you do, the SDK behaves exactly as before. This page covers the minimal setup; for every tunable option see the [Configuration & API Reference](/sdk/ios/offline-reference).

<Steps>

<Step title="Requirements">
Offline support requires CometChat iOS SDK **4.2.0** or later. Update the dependency:

{/* TODO(version): 4.2.0 is unreleased in the SDK changelog. Confirm the published pod/SPM version and whether a pre-release qualifier is needed. */}
<Tabs>
<Tab title="CocoaPods">
```ruby
pod 'CometChatSDK', '4.2.0'
```
</Tab>
<Tab title="Swift Package Manager">
Set the `https://github.com/cometchat/chat-sdk-ios.git` dependency rule to `Up to Next Major Version` with version `4.2.0`.
</Tab>
</Tabs>

If you are new to the SDK, complete the [standard setup](/sdk/ios/setup) first; the steps below only add offline configuration to your existing `init`.
</Step>

<Step title="Build an OfflineConfig">
Create an `OfflineConfig` and enable it. Every other field has a sensible default, so set only what you need. Swift can use the initializer with default arguments; the `Builder` works from both Swift and Objective-C.

<Tabs>
<Tab title="Initializer">
```swift
let offlineConfig = OfflineConfig(enabled: true)
```
</Tab>
<Tab title="Builder">
```swift
let offlineConfig = OfflineConfig.Builder()
    .setEnabled(true)
    .build()
```
</Tab>
</Tabs>
</Step>

<Step title="Attach it to AppSettings">
Pass the config to `AppSettingsBuilder.setOfflineConfig(_:)`. Without it, `AppSettings` keeps `OfflineConfig.default`, which has offline switched off.

```swift
let appSettings = AppSettings.AppSettingsBuilder()
    .setRegion(region: "REGION")
    .setOfflineConfig(offlineConfig)
    .build()
```
</Step>

<Step title="Initialize the SDK">
Pass the settings to `CometChat.init` as you do today. No other call changes.

```swift
CometChat.init(appId: "APP_ID", appSettings: appSettings, onSuccess: { isSuccess in
    print("Initialization completed successfully")
}, onError: { error in
    print("Initialization failed: \(error.errorDescription)")
})
```
</Step>

<Step title="Verify it is active">
Call `CometChat.isOfflineEnabled()`. It returns `true` only while offline support is actually available to the logged-in user: your `OfflineConfig` turns it on, CometChat has not switched offline off for your app, and the per-user cache is open. So it is `false` before anyone logs in and after logout, even when you enabled it in `AppSettings`. Read it at the moment of each decision and keep no copy of the result.

```swift
let active = CometChat.isOfflineEnabled()
print("Offline support active: \(active)")
```

<Note>
It is also `false` while the cache cannot run encrypted on this device and you chose `.onlineOnly` (see [Encrypt the Cache](/sdk/ios/offline-encryption)). It is already `true` by the time any `onLoginSuccess` observer runs.
</Note>
</Step>

</Steps>
