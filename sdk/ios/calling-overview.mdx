CometChat's Calls SDK adds voice and video calling to your iOS app, including 1-on-1 calls, group calls and conference sessions. It works on its own or alongside the Chat SDK.

## Key Features

- **Voice & Video Calls** — High-quality 1-on-1 and group calling with adaptive bitrate
- **Screen Sharing** — Share your screen during calls for collaboration
- **Call Recording** — Record calls and access recordings later
- **Call Logs** — Track call history with detailed metadata
- **Ringing** — Ring users and groups through CallKit with the Calls SDK v5 and the Push Notifications SDK 2.0
- **Customizable UI** — Presenter mode and video view customization

## Choose Your Version

<Warning>
**The Chat SDK's calling APIs are deprecated.** Ringing and call sessions now live in the Calls SDK
v5 and the Push Notifications SDK 2.0, and need no Chat SDK. The deprecated APIs still work, but
new apps shouldn't use them:

- Ringing: `CometChat.initiateCall`, `acceptCall`, `rejectCall`, `endCall`, `getActiveCall`, `clearActiveCall`
- Call events: `CometChat.calldelegate`, `addCallListener`, `removeCallListener`
- The Chat SDK's call engine: `CometChat.startCall`, `CometChat.getInstance()` and `CallManager`'s in-call controls, the `CallSettings.CallSettingsBuilder` class and the `CallSettings(builder:)` initializer
- `Call(receiverId:callType:receiverType:)`

This deprecation is in the Chat SDK only. The Calls SDK v4's own `CometChatCalls` methods, such as
`startSession`, `callSettingsBuilder`, `startRecording()` and `enterPIPMode()`, don't change.

To move from `CallSettings` to v5's `SessionSettingsBuilder`, see the
[builder method mapping](/calls/ios/migration-guide-v5#builder-method-mapping).

See [Ringing](/calls/ios/ringing) for the new flow and the
[ringing migration guide](/calls/ios/ringing-migration) to move an existing app.
</Warning>
