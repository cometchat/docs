## Quick Reference for AI Agents & Developers

```swift
// Configure secure media mode during SDK init
let appSettings = AppSettings.AppSettingsBuilder()
    .subscribePresenceForAllUsers()
    .setRegion(region: "YOUR_REGION")
    .setSecureMediaMode(.headerBased)
    .build()

CometChat.init(appId: "YOUR_APP_ID", appSettings: appSettings, onSuccess: { _ in
    print("Initialization completed successfully")
}, onError: { error in
    print("Initialization failed: \(error.errorDescription)")
})

// Fetch a time-limited presigned URL for secure media (Header-Based mode)
CometChat.fetchPresignedUrl(for: "https://files-<region>.cometchat.com/<app_id>/media/file.jpg",
    onSuccess: { presignedUrl in
        print("Presigned URL: \(presignedUrl)")
    },
    onError: { error in
        print("Error: \(error.errorDescription)")
    }
)

// Check if header-based mode is active
let isHeaderMode = Utils.shared.isHeaderModeEnabled()

// Check if a URL requires secure access
let needsSecure = Utils.shared.shouldInjectFatHeader(for: url)
```

Secure Media Access lets you control how media files (images, videos, audio, documents) are accessed on CometChat's secure media servers. The SDK supports two modes — Embedded (FAT appended as a query parameter automatically) and Header-Based (clean URLs where you fetch presigned URLs explicitly).

<Warning>
Once token based file access is enabled in the CometChat Dashboard, it cannot be disabled. All media URLs will require a valid File Access Token (FAT) for access. Make sure your application is ready to handle secure media URLs before enabling.
</Warning>

Available via: SDK | REST API | CometChat Dashboard

## Prerequisites

Before using Secure Media Access in your application, ensure the following:

1. **Enable in Dashboard**: Navigate to your CometChat Dashboard → Chats → Settings and enable the **Token Based File Access** configuration. This is a one-time setup step that activates token-based media access for your app.

2. **SDK Initialization**: Your application must initialize the CometChat SDK with a valid App ID and region before configuring secure media modes. See [Setup SDK](/sdk/ios/overview) for details.

<Note>
Once token based file access is enabled, all media URLs served by CometChat's secure media servers require a valid File Access Token (FAT) for access. Any request to a media URL without a valid FAT will receive a **401 Unauthorized** response. Ensure your application handles secure media URLs before enabling this feature.
</Note>

## Secure Media Modes

CometChat supports two modes for accessing media files on its secure media servers. The mode is configured during SDK initialization using `AppSettingsBuilder.setSecureMediaMode()`.

### Embedded Mode (Default)

Embedded Mode (`SecureMediaMode.embedded = 0`) is the default mode. In this mode, the SDK automatically appends the File Access Token (FAT) as a `?fat=<token>` query parameter to all media URLs. No additional work is required from the developer — media URLs are ready to use as-is.

- The SDK handles FAT injection transparently
- Media URLs include the token directly: `https://files-<region>.cometchat.com/<app_id>/media/file.jpg?fat=eyJhbGci...`
- Suitable for simple integrations where clean URLs are not a concern
- Works out of the box with `UIImageView`, `AVPlayer`, and other media components

### Header-Based Mode

Header-Based Mode (`SecureMediaMode.headerBased = 1`) provides clean media URLs without embedded tokens. In this mode, the developer is responsible for calling `CometChat.fetchPresignedUrl()` to resolve a time-limited presigned URL before rendering media.

- Media URLs remain clean without query parameters
- Developer calls `CometChat.fetchPresignedUrl(for:onSuccess:onError:)` to get a presigned URL at render time
- Presigned URLs are time-limited and grant temporary access to the media file
- Ideal for applications that need more security, clean URLs, or custom media handling logic

### SecureMediaMode Enum

<Tabs>
<Tab title="Swift">
```swift
@objc public enum SecureMediaMode: Int {
    case embedded = 0     // FAT in URL as ?fat=xxx (default)
    case headerBased = 1  // FAT sent via HTTP header (secure)
}
```
</Tab>
</Tabs>

| Mode | Value | Description |
| ---- | ----- | ----------- |
| `.embedded` | 0 | Default mode. FAT is appended as a `?fat=<token>` query parameter to media URLs automatically by the SDK. |
| `.headerBased` | 1 | Clean URL mode. Developer calls `CometChat.fetchPresignedUrl()` to resolve a time-limited presigned URL for media access. |

## Configuration

Configure the secure media mode during SDK initialization using `AppSettingsBuilder.setSecureMediaMode()`. Pass a value from the `SecureMediaMode` enum to select your preferred mode.

<Tabs>
<Tab title="Swift">
```swift
import CometChatSDK

let appId = "YOUR_APP_ID"
let region = "YOUR_REGION"

// Set up app settings with Header-Based secure media mode
let appSettings = AppSettings.AppSettingsBuilder()
    .subscribePresenceForAllUsers()
    .setRegion(region: region)
    .setSecureMediaMode(.headerBased)
    .autoEstablishSocketConnection(true)
    .build()

// Initialize the SDK with secure media mode configured
CometChat.init(appId: appId, appSettings: appSettings, onSuccess: { _ in
    print("Initialization completed successfully")
    // SDK is now configured for Header-Based secure media access
}, onError: { error in
    print("Initialization failed with error: \(error.errorDescription)")
})
```
</Tab>
</Tabs>

<Note>
If you omit `setSecureMediaMode()`, the SDK defaults to Embedded Mode (`SecureMediaMode.embedded`). In Embedded Mode, the SDK automatically appends the FAT as a query parameter to media URLs — no additional configuration is needed.
</Note>

## Fetching Presigned URLs

When using Header-Based Mode, call `CometChat.fetchPresignedUrl(for:onSuccess:onError:)` to resolve a time-limited presigned URL for any secure media file. The presigned URL grants temporary access to the media file without requiring additional authentication headers.

<Tabs>
<Tab title="Swift">
```swift
// Fetch a presigned URL for a secure media file
let mediaUrl = "https://files-<region>.cometchat.com/<app_id>/media/file.jpg"

CometChat.fetchPresignedUrl(
    for: mediaUrl,
    onSuccess: { presignedUrl in
        print("Presigned URL: \(presignedUrl)")
        // Use the presigned URL to render the media (e.g., set as UIImageView image)
    },
    onError: { error in
        print("Error fetching presigned URL: \(error.errorDescription)")
    }
)
```
</Tab>
</Tabs>

### Parameters

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| url | `String` | The secure media URL to resolve. Must point to a file hosted on CometChat's secure media servers. |
| onSuccess | `(String) -> Void` | Callback with the presigned URL string. |
| onError | `(CometChatException) -> Void` | Callback with error details. |

### Return Value

| Type | Description |
| ---- | ----------- |
| `String` (via callback) | A time-limited presigned URL that grants temporary access to the media file. |

## How Attachment URLs Differ

When Secure Media Access is enabled, the format of media attachment URLs depends on the configured mode. Understanding this difference is important for rendering media correctly in your application.

### Embedded Mode

In Embedded Mode, the SDK automatically appends the File Access Token (FAT) as a `?fat=<token>` query parameter to every media URL. Attachment URLs returned by the SDK are ready to use directly — no additional processing is needed.

```
https://files-<region>.cometchat.com/<app_id>/media/file.jpg?fat=eyJhbGciOiJIUzI1NiIs...
```

- URLs are self-contained and can be used directly with `UIImageView`, `AVPlayer`, or other media components
- The SDK handles token injection transparently when you access attachment URLs from message objects
- No developer action is required at render time

### Header-Based Mode

In Header-Based Mode, attachment URLs remain clean without any token parameters. The developer must explicitly call `CometChat.fetchPresignedUrl()` at render time to resolve a time-limited presigned URL before displaying the media.

```
https://files-<region>.cometchat.com/<app_id>/media/file.jpg
```

- URLs do not contain any token information
- Before rendering, call `CometChat.fetchPresignedUrl(for:onSuccess:onError:)` to get a presigned URL
- The presigned URL is time-limited — fetch a new one if it expires
- Gives you full control over when and how media files are loaded

<Info>
In Embedded Mode, you can use attachment URLs directly from message objects. In Header-Based Mode, always resolve the URL with `CometChat.fetchPresignedUrl()` before passing it to an image or media element.
</Info>

## Methods and Helpers

The following static members are available on the `CometChat` class for working with Secure Media Access:

| Member | Type | Description |
| ------ | ---- | ----------- |
| `CometChat.SecureMediaMode` | `enum` | Enum with two values: `.embedded` (0) and `.headerBased` (1). Used with `AppSettingsBuilder.setSecureMediaMode()` to configure the secure media access mode. |
| `CometChat.getFat()` | `() -> String?` | Returns the decoded File Access Token (FAT) for the current session, or `nil` if no valid FAT is available. |
| `CometChat.fetchPresignedUrl(for:onSuccess:onError:)` | `(String, (String) -> Void, (CometChatException) -> Void) -> Void` | Resolves a time-limited presigned URL for the given secure media URL. Used in Header-Based Mode to get a temporary URL that grants access to the media file. |

### Helper Methods

The `Utils.shared` class provides utility methods to check the current secure media configuration at runtime. These are synchronous methods that return values directly.

#### isHeaderModeEnabled()

Returns `true` when all three conditions are met: the secure media mode is set to `.headerBased`, a valid FAT exists for the current session, and the secure media host is configured.

<Tabs>
<Tab title="Swift">
```swift
// Check if Header-Based mode is fully active
let isEnabled = Utils.shared.isHeaderModeEnabled()
print("Header-Based mode enabled: \(isEnabled)")

if isEnabled {
    // Use CometChat.fetchPresignedUrl() before rendering media
    print("Resolve media URLs with fetchPresignedUrl() before rendering")
} else {
    // Embedded mode or not configured — URLs are ready to use as-is
    print("Media URLs can be used directly")
}
```
</Tab>
</Tabs>

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| — | — | This method takes no parameters. |

| Return Type | Description |
| ----------- | ----------- |
| `Bool` | `true` if the mode is `.headerBased`, a valid FAT exists, and the secure media host is configured. `false` otherwise. |

#### shouldInjectFatHeader(for:)

Returns `true` if the given URL points to the configured secure media host. Use this to determine whether a URL needs to be resolved via `CometChat.fetchPresignedUrl()` before rendering.

<Tabs>
<Tab title="Swift">
```swift
// Check if a URL requires secure access
let mediaUrl = URL(string: "https://files-<region>.cometchat.com/<app_id>/media/file.jpg")!
let needsSecure = Utils.shared.shouldInjectFatHeader(for: mediaUrl)
print("Requires secure access: \(needsSecure)")

if needsSecure && Utils.shared.isHeaderModeEnabled() {
    // Resolve the URL before rendering
    CometChat.fetchPresignedUrl(
        for: mediaUrl.absoluteString,
        onSuccess: { presignedUrl in
            print("Use this URL to render media: \(presignedUrl)")
        },
        onError: { error in
            print("Error fetching presigned URL: \(error.errorDescription)")
        }
    )
} else {
    // URL does not require secure access or Embedded mode handles it
    print("Use the URL directly: \(mediaUrl)")
}
```
</Tab>
</Tabs>

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| url | `URL` | The media URL to check. The method compares the URL's host against the configured secure media host. |

| Return Type | Description |
| ----------- | ----------- |
| `Bool` | `true` if the URL points to the configured secure media host. `false` otherwise. |

### Additional Utils Methods

| `stripFatQueryParam(from: URL)` | Removes FAT query parameter from URL | `URL` |

## Usage Examples

### Loading Images with URLSession (Header-Based Mode)

<Tabs>
<Tab title="Swift">
```swift
func loadImage(from urlString: String, into imageView: UIImageView) {
    // First, fetch the presigned URL
    CometChat.fetchPresignedUrl(
        for: urlString,
        onSuccess: { presignedUrl in
            guard let url = URL(string: presignedUrl) else { return }
            
            URLSession.shared.dataTask(with: url) { data, _, error in
                if let data = data, let image = UIImage(data: data) {
                    DispatchQueue.main.async {
                        imageView.image = image
                    }
                }
            }.resume()
        },
        onError: { error in
            print("Error fetching presigned URL: \(error.errorDescription)")
        }
    )
}

// Usage
loadImage(from: mediaMessage.attachment?.fileUrl ?? "", into: myImageView)
```

### Downloading Files (Header-Based Mode)

<Tabs>
<Tab title="Swift">
```swift
func downloadFile(from urlString: String, completion: @escaping (URL?) -> Void) {
    CometChat.fetchPresignedUrl(
        for: urlString,
        onSuccess: { presignedUrl in
            guard let url = URL(string: presignedUrl) else {
                completion(nil)
                return
            }
            
            URLSession.shared.downloadTask(with: url) { tempURL, _, error in
                guard let tempURL = tempURL else {
                    completion(nil)
                    return
                }
                
                let documentsPath = FileManager.default.urls(for: .documentDirectory, in: .userDomainMask)[0]
                let destinationURL = documentsPath.appendingPathComponent(url.lastPathComponent)
                
                try? FileManager.default.removeItem(at: destinationURL)
                try? FileManager.default.moveItem(at: tempURL, to: destinationURL)
                
                completion(destinationURL)
            }.resume()
        },
        onError: { error in
            print("Error: \(error.errorDescription)")
            completion(nil)
        }
    )
}
```
</Tab>
</Tabs>

## Error Handling

When working with Secure Media Access, handle these common error scenarios gracefully in your application.

### Feature Not Enabled

If Secure Media Access is not enabled in the CometChat Dashboard, calling `CometChat.fetchPresignedUrl()` will not throw an error — it simply returns the same URL string that was passed in. Media URLs work normally without a File Access Token in this case.

<Tabs>
<Tab title="Swift">
```swift
// Calling fetchPresignedUrl when the feature is not enabled
let mediaUrl = "https://example.com/file.jpg"

CometChat.fetchPresignedUrl(
    for: mediaUrl,
    onSuccess: { returnedUrl in
        // returnedUrl == mediaUrl — the same URL is returned as-is
        print("Returned URL: \(returnedUrl)")
    },
    onError: { error in
        print("Error: \(error.errorDescription)")
    }
)
```
</Tab>
</Tabs>

### Invalid URL Provided

If an invalid or malformed URL is passed to `CometChat.fetchPresignedUrl()`, the method does not throw an error — it returns the same string that was passed in.

<Tabs>
<Tab title="Swift">
```swift
// Passing an invalid URL to fetchPresignedUrl
let invalidUrl = "not-a-valid-url"

CometChat.fetchPresignedUrl(
    for: invalidUrl,
    onSuccess: { returnedUrl in
        // returnedUrl == invalidUrl — the same string is returned as-is
        print("Returned URL: \(returnedUrl)")
    },
    onError: { error in
        print("Error: \(error.errorDescription)")
    }
)
```
</Tab>
</Tabs>

### Expired File Access Token (FAT)

When the File Access Token expires, media requests return a **401 Unauthorized** response. The SDK automatically refreshes the FAT on re-login. In your application, handle 401 responses by re-fetching the presigned URL.

<Tabs>
<Tab title="Swift">
```swift
// Handle expired FAT by re-fetching the presigned URL
let mediaUrl = "https://files-<region>.cometchat.com/<app_id>/media/file.jpg"

func loadSecureMedia(url: String) {
    CometChat.fetchPresignedUrl(
        for: url,
        onSuccess: { presignedUrl in
            print("Presigned URL: \(presignedUrl)")
            // Use the presigned URL to render media
        },
        onError: { error in
            print("Error fetching presigned URL: \(error.errorDescription)")
            // If FAT expired, the SDK refreshes it on next login
            // Retry after re-authentication if needed
        }
    )
}

loadSecureMedia(url: mediaUrl)
```
</Tab>
</Tabs>

## Best Practices

### Cache Presigned URLs Appropriately

Presigned URLs are time-limited. Cache them only for short durations and always be prepared to fetch a new one if the cached URL expires.

### Refresh Expired URLs

Implement retry logic to handle expired presigned URLs. When you receive a 401 or 403 response, fetch a fresh presigned URL and retry the request.

### Handle 401 Responses Gracefully

When media requests fail with 401 Unauthorized, check if the user is still logged in and if the FAT is valid. Re-authenticate if necessary.

### Choose Between Embedded and Header-Based Modes

- Use **Embedded Mode** for simple integrations where clean URLs are not a concern
- Use **Header-Based Mode** when you need clean URLs, enhanced security, or custom media handling logic

## Troubleshooting

### 401 Unauthorized on Media URLs

**Symptom:** Media files fail to load and the server returns a 401 Unauthorized response.

**Possible causes:**
- Secure Media Access is enabled in the Dashboard but the SDK is not configured with a secure media mode
- The File Access Token (FAT) has expired or is missing
- In Header-Based Mode, you are using the raw media URL instead of a presigned URL

**Solution:**
- Verify that `setSecureMediaMode()` is called during SDK initialization
- In Header-Based Mode, always call `CometChat.fetchPresignedUrl(for:onSuccess:onError:)` before rendering media
- If the FAT has expired, re-authenticate the user — the SDK refreshes the FAT on login
- Use `CometChat.getFat()` to check if a valid FAT exists for the current session

### Expired Presigned URLs

**Symptom:** A presigned URL that previously worked now returns a 401 or 403 response.

**Cause:** Presigned URLs are time-limited. Once the URL expires, it can no longer be used to access the media file.

**Solution:**
- Discard the expired presigned URL from any local cache
- Call `CometChat.fetchPresignedUrl(for:onSuccess:onError:)` again with the original media URL to get a fresh presigned URL
- Implement a retry mechanism in your media loading logic to handle expired URLs automatically

### Mode Mismatch Between SDK and Media URLs

**Symptom:** Media URLs contain `?fat=<token>` when you expect clean URLs, or vice versa.

**Cause:** The SDK is configured in a different mode than expected. For example, the SDK is in Embedded Mode but your code assumes Header-Based Mode.

**Solution:**
- Check the configured mode using `Utils.shared.isHeaderModeEnabled()`
- Verify the `setSecureMediaMode()` value passed during SDK initialization
- In Embedded Mode (`.embedded`), URLs automatically include `?fat=<token>` — do not call `fetchPresignedUrl()`
- In Header-Based Mode (`.headerBased`), URLs are clean — always call `fetchPresignedUrl()` before rendering
