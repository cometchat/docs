With offline support on, the SDK can cache attachment bytes durably on the device so media stays viewable offline — even after the server's presigned URL has expired. This page covers the caching modes, what downloads automatically, how to read cached bytes, and how to download media on demand.

<Note>
Media caching applies only while offline support is active for the logged-in user (`CometChat.isOfflineEnabled()` is `true`), and needs the optional `react-native-fs` peer dependency. See [Enable Offline Support](/sdk/react-native/offline-enable).
</Note>

<Warning>
On recent React Native versions, `react-native-fs` 2.20.0 can crash the app on Android when a download loses the network part-way. Use the maintained fork under the same module name (`"react-native-fs": "npm:@dr.pogodin/react-native-fs@~2.40.4"`; it needs the New Architecture and React Native 0.73+, and has no default export), patch `RNFSManager.reject`, or set `mediaCaching` to `OFF`.
</Warning>

## Caching modes

The caching mode is set once, in the `OfflineConfig` you pass at initialization, and is fixed for the SDK session. There is no runtime switch — to change it, re-initialize the SDK with a new config.

| `MediaCachingMode` | Behavior |
|---|---|
| `AUTO` (default) | Incoming media bytes are eagerly downloaded and cached on any network, then LRU-managed. The outgoing copy is retained after the server acknowledges the send. |
| `OFF` | Incoming media bytes are **not** cached. The message metadata (including the file URL) is still cached, so the message appears offline and the UI loads media live from the URL when online. The outgoing copy is dropped after the send is acknowledged. |

Sending media always works in both modes.

```typescript
const offlineConfig = new CometChat.OfflineConfig({
  enabled: true,
  mediaCaching: CometChat.MediaCachingMode.AUTO,
  maxMediaCacheSize: 500 * 1024 * 1024,
});
```

Read the mode in effect at runtime with `CometChat.getMediaCachingMode()`. It returns `MediaCachingMode.OFF` whenever offline support is not active, whatever the app configured, so a UI layer can rely on it without reading the config itself.

## What downloads automatically

In `AUTO` mode, media bytes are downloaded and cached automatically on the two live receive paths:

- a **realtime** media message received while connected, and
- opening a chat **online** (the server read refreshes and caches its media).

A media message that arrives through a reconnect catch-up [sync](/sdk/react-native/offline-sync) is cached as **metadata only** and renders as a placeholder; its bytes download lazily the next time you open that chat online. This holds in both `AUTO` and `OFF`.

In `OFF` mode, nothing is auto-downloaded on any path; media loads live from its URL when online.

## Reading cached media

When bytes are already cached, the SDK **hydrates the local path automatically** on every message it delivers — you do not have to ask. Read it straight off the attachment:

```typescript
const attachment = mediaMessage.getAttachment();
const localPath = attachment.getLocalPath(); // defined when bytes are cached
if (localPath) {
  // Render directly from disk — no network fetch.
}
```

To look up the cached path explicitly, call `getCachedMediaPath`. It never downloads, and resolves `null` when the bytes are not cached (call `downloadMedia` to fetch them). It accepts a `MediaMessage` or a bare `Attachment`.

```typescript
const path: string | null = await CometChat.getCachedMediaPath(attachment);
```

<Note>
Each attachment of a multi-attachment message resolves independently. An attachment with no cached bytes has no local path and the UI loads it from the URL as before.
</Note>

## Downloading on demand

Call `downloadMedia` to fetch and cache an attachment's bytes — for example when the user taps a placeholder. The SDK resolves cached bytes first, then a valid URL, then a re-signed URL if the presigned one expired. The Promise resolves with the local path, and also sets it on the attachment. It resolves `null` if the bytes could not be obtained, or if offline support is off.

<Tabs>
<Tab title="TypeScript">
```typescript
const path: string | null = await CometChat.downloadMedia(attachment, {
  onMediaDownloaded: (messageId: string, attachmentKey: string, localPath: string) => {
    // Bytes cached; render from localPath.
  },
  onMediaProgress: (messageId: string, attachmentKey: string, percent: number) => {
    // 0..100, best-effort.
  },
  onMediaDownloadFailed: (messageId: string, attachmentKey: string, error: { code: string; message: string }) => {
    console.log(error.code); // MEDIA_OFFLINE_NOT_CACHED | MEDIA_DOWNLOAD_FAILED | ERROR_OFFLINE_DISABLED
  },
});
```
</Tab>
<Tab title="JavaScript">
```javascript
const path = await CometChat.downloadMedia(attachment, {
  onMediaDownloaded: (messageId, attachmentKey, localPath) => {
    // Bytes cached; render from localPath.
  },
  onMediaProgress: (messageId, attachmentKey, percent) => {
    // 0..100, best-effort.
  },
  onMediaDownloadFailed: (messageId, attachmentKey, error) => {
    console.log(error.code); // MEDIA_OFFLINE_NOT_CACHED | MEDIA_DOWNLOAD_FAILED | ERROR_OFFLINE_DISABLED
  },
});
```
</Tab>
</Tabs>

`onMediaProgress(…, percent)` reports `0..100`, best-effort. It is emitted only when the server reports a content length; for an unknown-length download it is skipped and the call goes straight to `onMediaDownloaded`. Progress never blocks or fails the download. All three callbacks are optional.

The listener also accepts the shorter shape `{ onSuccess(localPath), onProgress(percent), onError(error) }`.

## Observe background downloads

In `AUTO` mode, incoming media downloads in the background with no per-call callback. Register a media download listener to learn when the bytes land (or fail) so a UI tile can refresh.

<Tabs>
<Tab title="TypeScript">
```typescript
await CometChat.addMediaDownloadListener("MEDIA_LISTENER", {
  onMediaDownloaded: (messageId: string, attachmentKey: string, localPath: string) => {
    // messageId:     the message's server id (or local id if not yet sent)
    // attachmentKey: the attachment URL without its query string
    // localPath:     where the bytes landed
  },
  onMediaDownloadFailed: (messageId: string, attachmentKey: string, error: { code: string; message: string }) => {},
});
```
</Tab>
<Tab title="JavaScript">
```javascript
await CometChat.addMediaDownloadListener("MEDIA_LISTENER", {
  onMediaDownloaded: (messageId, attachmentKey, localPath) => {
    // messageId:     the message's server id (or local id if not yet sent)
    // attachmentKey: the attachment URL without its query string
    // localPath:     where the bytes landed
  },
  onMediaDownloadFailed: (messageId, attachmentKey, error) => {},
});
```
</Tab>
</Tabs>

Remove the listener with `CometChat.removeMediaDownloadListener("MEDIA_LISTENER")`. The background listener carries no progress callback — progress is reported only on the explicit `downloadMedia` path above.

## Media cache size limit

Cached media bytes are bounded by `maxMediaCacheSize` (default **500 MB**; `0` means unlimited). When the cache exceeds the limit, the least recently accessed media is deleted first until it is back under budget. Media belonging to un-sent messages and in-progress uploads is never evicted and does not count toward the budget.

Media is stored as files in an app-private, per-user directory; the location is not configurable. Eviction runs silently in the background — there is no cache-limit callback. To reason about size, use `CometChat.getCacheSize()` and the configured limits. See the [configuration reference](/sdk/react-native/offline-reference) for the full set of options.
