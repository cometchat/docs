A **Bot** is an existing user that also has a webhook. Once a bot is enabled, CometChat relays the messages it receives to the bot's `webhookURL`, and your service replies by calling the [Send Bot Message API](/rest-api/messages/send-bot-message).

### Endpoints

| Method | Endpoint | Description |
| ------ | -------- | ----------- |
| POST   | [`/bots`](/rest-api/bots/create) | Create a new bot |
| GET    | [`/bots`](/rest-api/bots/list) | List all bots |
| GET    | [`/bots/{uid}`](/rest-api/bots/get) | Get a specific bot |
| PUT    | [`/bots/{uid}`](/rest-api/bots/update) | Update a bot |
| DELETE | [`/bots/{uid}`](/rest-api/bots/delete) | Delete a bot |

### How bots work

- A bot is a **user plus a webhook**. The `uid` you pass to the Create Bot API must already belong to a [User](/rest-api/users); if it does not, the API returns `ERR_UID_NOT_FOUND`.
- One-to-one messages sent to the bot are relayed to its `webhookURL`.
- Group messages are relayed according to `groupChatSetting`:

| Value | Messages relayed to the webhook |
| ----- | ------------------------------- |
| `allMessages` | Every message in groups the bot belongs to |
| `slashedMessages` | Only messages beginning with a slash command |
| `mentionedMessages` | Only messages that mention the bot |
| `none` | No group messages. This is the default. |

- A bot only relays messages while `enabled` is `true`.
- Set `useBasicAuth` to `true` to send HTTP basic auth credentials with every webhook call, so your endpoint can verify the caller.
- Bots reply through the [Send Bot Message API](/rest-api/messages/send-bot-message), which posts a message as the bot.

<Warning>
When `useBasicAuth` is `true`, the API returns the stored `password` value in responses to Create, List, Get and Update. A `GET /bots` response therefore contains the basic auth credentials of every bot in the app. Treat those responses as secrets, and restrict who can use the API key that reads them.
</Warning>

### Relationships

- **Users** — A bot is a [User](/rest-api/users) with a webhook attached. Its name and avatar belong to the user, so change them with the [Update User API](/rest-api/users/update).
- **Send Bot Message** — Use the [Send Bot Message API](/rest-api/messages/send-bot-message) to post a message as a bot.
- **Custom Bots** — For an end-to-end walkthrough, including the webhook payload your service receives, see the [Custom Bots guide](/ai-chatbots/custom-bots).

### Bot properties

| Property | Type | Description |
| -------- | ---- | ----------- |
| **uid** | string | UID of the user this bot belongs to. Forced to lowercase. |
| **webhookURL** | string | URL that receives the messages relayed to the bot. |
| **groupChatSetting** | string | Which group messages are relayed. One of `allMessages`, `slashedMessages`, `mentionedMessages`, `none`. |
| **useBasicAuth** | boolean | Whether basic auth credentials are sent with each webhook call. |
| **username** | string | Basic auth username. Stored only when `useBasicAuth` is `true`. |
| **password** | string | Basic auth password. Stored only when `useBasicAuth` is `true`, and returned in responses as stored. |
| **enabled** | boolean | Whether the bot relays messages to its webhook. Defaults to `false`. |
| **isAIBot** | boolean | Whether this is an AI bot. AI bots are created through AI Agents, and are returned only when you pass `isAIBot=true` to the List Bots API. |
| **createdAt** | integer | UNIX timestamp of when the bot was created. |
| **updatedAt** | integer | UNIX timestamp of the last update. Absent until the bot is updated. |

<Note>
Responses omit every property whose value is empty or `false`. A bot with `useBasicAuth` set to `false` has no `useBasicAuth`, `username` or `password` in its response, and a standard bot has no `isAIBot`.
</Note>

### Error handling

| Error Code | Description |
| ---------- | ----------- |
| `ERR_BOT_NOT_FOUND` | No bot exists with the specified UID |
| `ERR_UID_NOT_FOUND` | No user exists with the specified UID |
| `ERR_PLAN_RESTRICTION` | Your plan does not include bots |
| `ERR_BAD_REQUEST` | The request failed validation, for example a duplicate bot UID |

For the complete list of error codes, see [Error Guide](/articles/error-guide).

For all system limits (bot caps, UID length, etc.), see [Properties and Constraints](/articles/properties-and-constraints).
