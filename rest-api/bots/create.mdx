---
openapi: post /bots
description: "Create a CometChat bot for an existing user with the REST API and relay its messages to your own webhook."
---

The `uid` must already belong to a [User](/rest-api/users). If no such user exists, the API returns `ERR_UID_NOT_FOUND`.

`groupChatSetting` defaults to `none`, so a new bot receives no group messages until you set it. `username` and `password` are stored only when `useBasicAuth` is `true`; otherwise they are discarded.

A bot's name and avatar belong to its user, not to the bot — set them with the [Update User API](/rest-api/users/update).

## Constraints

| Item | Constraint | Notes |
| ---- | ---------- | ----- |
| Bot UID | 50 characters | Must match an existing user. CometChat forces the UID to lowercase |
| Webhook URL | 255 characters | Must be a valid URL |
| Basic auth username | 50 characters | Ignored unless `useBasicAuth` is `true` |
| Basic auth password | 50 characters | Ignored unless `useBasicAuth` is `true` |
| Bots per app | 25 bot users | See [Properties and Constraints](/articles/properties-and-constraints) |

<Warning>
When `useBasicAuth` is `true`, the API returns the stored `password` value in the response. The example masks it as `********`; a real response contains the password you sent.
</Warning>

For the complete error reference, see [Error Guide](/articles/error-guide).
